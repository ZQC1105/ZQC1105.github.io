## **核心理念：声明式 vs 命令式**

### **传统面向对象方式（命令式）**

```csharp
// 关注"怎么做" - 显式的条件判断
public string ProcessShape(object shape)
{
    if (shape is Circle circle)
    {
        return $"圆形，半径：{circle.Radius}";
    }
    else if (shape is Rectangle rect)
    {
        return $"矩形，宽：{rect.Width}，高：{rect.Height}";
    }
    else if (shape is Triangle triangle)
    {
        return $"三角形，边：{triangle.Side1}, {triangle.Side2}, {triangle.Side3}";
    }
    else
    {
        return "未知形状";
    }
}
```

### **函数式风格+模式匹配（声明式）**


## **三大核心联系**

### **1. 代数数据类型（ADT）的思想**

**函数式语言的核心概念**：

```fsharp
// F#中的 discriminated union（C#缺少的原生支持）
type Shape =
    | Circle of radius: float
    | Rectangle of width: float * height: float
    | Triangle of side1: float * side2: float * side3: float

// 模式匹配是处理ADT的自然方式
let area shape =
    match shape with
    | Circle r -> Math.PI * r * r
    | Rectangle (w, h) -> w * h
    | Triangle (a, b, c) ->
        let s = (a + b + c) / 2.0
        sqrt(s * (s - a) * (s - b) * (s - c))
```

**C#通过模式匹配逼近**：

```csharp
// C#使用模式匹配处理类似场景
public double Area(object shape) => shape switch
{
    Circle c => Math.PI * c.Radius * c.Radius,
    Rectangle r => r.Width * r.Height,
    Triangle t =>
    {
        var s = (t.Side1 + t.Side2 + t.Side3) / 2;
        return Math.Sqrt(s * (s - t.Side1) * (s - t.Side2) * (s - t.Side3));
    },
    _ => throw new ArgumentException("未知形状")
};
```

### **2. 不可变性与穷尽性检查**

**函数式核心原则**：

```csharp
// 不可变数据 + 模式匹配 = 编译时安全保障
public record Result<T>(T? Value, string? Error);

public T ProcessResult<T>(Result<T> result)
{
    return result switch
    {
        // 编译器可以检查是否覆盖了所有情况
        { Value: not null, Error: null } => result.Value,
        { Error: not null } => throw new Exception(result.Error),

        // 如果漏掉了某个case，现代IDE会警告
    };
}

// 对比传统方式 - 容易遗漏null检查
public T ProcessResultOld(Result<T> result)
{
    if (result.Value != null)
    {
        return result.Value; // 可能忘记检查Error
    }
    // 可能忘记处理Error不为null的情况
}
```

```csharp
// 函数式风格的状态处理
public interface IOrderState;
public record Pending : IOrderState;
public record Approved(string Approver) : IOrderState;
public record Rejected(string Reason) : IOrderState;

public IOrderState ProcessOrder(IOrderState current, Command command) =>
    (current, command) switch
    {
        // 声明式状态转换规则
        (Pending, ApproveCommand c) => new Approved(c.ApproverName),
        (Pending, RejectCommand c) => new Rejected(c.Reason),

        // 编译器会警告未覆盖的组合
        _ => throw new InvalidOperationException($"无效状态转换：{current} + {command}")
    };
```

## **哲学层面的联系**

### **1. 数学基础**

- **模式匹配** ≈ **代数结构的分解**
- **函数式编程** ≈ **Lambda演算的应用**
- 两者都强调**结构分解**而非**过程控制**

### **2. 认知模型**

```csharp
// 传统方式：像流程图

else if (condition2) { /* 分支2 */ }
else { /* 默认 */ }

// 函数式+模式匹配：像数学定义

  | case1 -> result1
  | case2 -> result2
  | otherwise -> default
```

```csharp
// BEFORE: 嵌套的条件逻辑
public decimal CalculatePrice(Order order, Customer customer)
{
    if (order == null) throw new ArgumentNullException();
    if (customer == null) throw new ArgumentNullException();

    decimal basePrice = order.Items.Sum(i => i.Price * i.Quantity);

    if (customer.IsVIP)
    {
        if (order.Items.Count > 5)
            return basePrice * 0.8m;
        else
            return basePrice * 0.9m;
    }
    else if (customer.IsRegular)
    {
        return basePrice * 0.95m;
    }
    else
    {
        return basePrice;
    }
}

// AFTER: 声明式的规则集合
public decimal CalculatePrice(Order order, Customer customer) =>
    (order, customer) switch
    {
        (null, _) => throw new ArgumentNullException(nameof(order)),
        (_, null) => throw new ArgumentNullException(nameof(customer)),

        var (o, c) when c.IsVIP && o.Items.Count > 5 =>
            o.Items.Sum(i => i.Price * i.Quantity) * 0.8m,

        var (o, c) when c.IsVIP =>
            o.Items.Sum(i => i.Price * i.Quantity) * 0.9m,

        var (o, c) when c.IsRegular =>
            o.Items.Sum(i => i.Price * i.Quantity) * 0.95m,

        var (o, _) => o.Items.Sum(i => i.Price * i.Quantity)
    };
```

## **总结联系**

模式匹配和函数式风格之所以联系紧密，是因为它们都代表了同一种**思维范式转换**：

| 维度         | 传统命令式 | 函数式+模式匹配   |
| ------------ | ---------- | ----------------- |
| **关注点**   | 控制流程   | 数据结构          |
| **思维模式** | 如何做     | 是什么            |
| **代码组织** | 语句序列   | 表达式树          |
| **错误处理** | 异常抛出   | 返回Result/Option |
| **状态管理** | 可变变量   | 不可变值          |
| **组合方式** | 方法调用链 | 函数组合          |

**本质上，模式匹配是函数式编程处理复杂数据结构的"眼睛"和"手臂"**。没有模式匹配，函数式语言处理复杂数据类型会很笨拙；而没有函数式的不变性和表达式思维，模式匹配也难以发挥最大威力。
