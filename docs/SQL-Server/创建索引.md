## [聚集与非聚集索引](https://learn.microsoft.com/zh-cn/sql/relational-databases/indexes/create-clustered-indexes?view=sql-server-ver16)

我们来详细对比一下数据库（以SQL Server为代表）中的**聚集索引（Clustered Index）**和**非聚集索引（Nonclustered Index）**。

可以把数据库表想象成一本书，这样对比会更形象：

### 核心概念类比

- **表（书的内容）**：包含所有数据的实体。
- **聚集索引（正文本身）**：书的内容本身就是按照页码顺序（比如汉语拼音A-Z）排列好的。找到A开头的部分，你就直接翻到了那一页。
- **非聚集索引（书后的附录/索引表）**：书后面附带的“关键词索引”，比如“数据库：第100页”。它列出了关键词和对应的页码，但正文本身并不是按关键词顺序排列的。

---

### 详细对比表格

| 特性                          | 聚集索引 （Clustered Index）                                                                                                                                     | 非聚集索引 （Nonclustered Index）                                                                                                                                                                             |
| :---------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1. 数据存储方式**           | **决定了表的物理存储顺序。** 索引的叶子节点（最底层）就是实际的数据行。可以说，表数据本身就是按照索引列排序存储的。                                              | **不改变数据的物理存储顺序。** 索引是一个独立的结构，它的叶子节点包含的是索引列的值，以及一个指向实际数据行的“指针”（书签查找）。                                                                             |
| **2. 数量限制**               | **一个表只能有一个聚集索引。** 因为数据物理顺序只能有一种。                                                                                                      | **一个表可以有多个非聚集索引。** （通常建议不超过5-10个，视具体业务和写负载而定）因为可以有多份不同的“目录”。                                                                                                 |
| **3. 查询速度**               | **对于范围查询（如 WHERE Age BETWEEN 18 AND 25）和点查询（如 WHERE ID = 1），速度极快。** 一旦找到第一个符合条件的值，后面的数据在物理上是连续的，可以顺序读取。 | **查询速度通常取决于“回表”操作。** 如果在非聚集索引中找到了所需数据的“指针”，还需要拿着这个“指针”去实际数据页（通常是聚集索引）查找完整数据。如果查询的列刚好都在索引里（覆盖索引），则不需要回表，速度极快。 |
| **4. 磁盘空间**               | **不额外占用大量空间来存储索引结构。** 因为索引就是数据本身。                                                                                                    | **需要额外的磁盘空间来存储索引结构。** 索引越多，占用的空间越大。                                                                                                                                             |
| **5. 对插入/更新/删除的影响** | **影响较大。** 当插入或更新数据，导致需要改变行的物理位置时（比如插入一行ID=2.5，需要把2.5之后的所有行往后挪），可能会引起数据页的分裂和重组，消耗较大性能。     | **影响相对较小，但并非没有。** 每次对数据的修改，都需要同时维护所有的非聚集索引。一张表如果有5个非聚集索引，执行INSERT操作时，除了写入数据，还要同时更新这5个“目录”。                                         |
| **6. 默认创建场景**           | 创建**主键（Primary Key）** 时，默认会创建聚集索引（除非特别指定为非聚集）。                                                                                     | 创建**UNIQUE约束**时，默认创建的是非聚集索引。创建普通的**INDEX**（索引）时，默认也是非聚集。                                                                                                                 |

### 图解理解

#### 1. 聚集索引 （Clustered Index）

如果把表想象成一个Excel表格，数据按A列排序后保存。

- **结构**：
  - 根节点/中间节点：存储索引列的键值和指向下一级的指针。
  - **叶子节点：就是数据行本身。**
- **查找过程**：例如，要找学号=102的学生。
  - 从根节点开始查找。
  - 找到包含102的页范围。
  - 直接定位到该数据页，读取整行数据（姓名、年龄等）。

#### 2. 非聚集索引 （Nonclustered Index）

如果把表想象成一本书，数据按章节排列，后面附有“关键词索引”。

- **结构**：
  - 根节点/中间节点：存储索引列的值和指向下一级的指针。
  - **叶子节点：存储索引列的值 + “书签”（Row ID或聚集索引键）。**
- **查找过程**：例如，要通过“姓名”索引找姓名为“张三”的学生。
  - 在“姓名索引”的树中查找“张三”。
  - 在叶子节点找到“张三”对应的“书签”（比如聚集索引键=102，或者物理地址RID）。
  - 拿着“书签”（102）去聚集索引（或堆表）中进行第二次查找（这个过程叫**书签查找**或**键查找**），才能读到整行数据。

### 如何选择与设计建议

1.  **主键选择**：
    - 通常建议将**自增列（IDENTITY）** 或**单调递增的列**作为聚集索引。这样可以保证新数据总是追加到末尾，减少页分裂，提升写入性能。
2.  **高频查询列**：
    - 如果某个列经常被用于**范围查询**（BETWEEN、>、<）或**排序（ORDER BY）**，可以考虑将其设为聚集索引（前提是这个表还没有聚集索引）。因为数据物理有序，读取效率极高。
3.  **避免过宽键值**：
    - 聚集索引的键值应尽可能短（比如用int，不用varchar(500)）。因为**所有非聚集索引的叶子节点都会包含聚集索引的键值**用于回表定位。如果聚集索引键很大，所有非聚集索引都会变得臃肿。
4.  **覆盖索引策略**：
    - 如果一个查询需要返回的列，正好全部包含在非聚集索引中（或者加上聚集索引键），那么数据库可以直接在索引页拿到所有数据，**无需回表**。这被称为“覆盖索引”，可以极大提升查询性能。
