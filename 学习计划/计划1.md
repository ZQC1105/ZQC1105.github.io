## 中模系统引入AI服务 用于查询显示

**OpenTelemetry（简称OTel）是一个开度的可观测性框架，可以理解为“为软件系统安装黑匣子”的统一标准。**

在AI Agent这种复杂的多步骤系统中，它解决了核心问题：**当Agent调用多个工具、经历多轮思考时，如何知道内部发生了什么、哪里慢了、哪里出错了？**

---

## 一、用外卖Agent类比理解

假设你有一个外卖Agent，用户说“帮我退款”。

**没有OTel时**：你只知道“用户说退款，Agent说已处理”。中间发生了什么？调用订单API花了2秒？还是退款API失败了？完全不知道。

**有OTel时**，你可以看到完整的“调用链”：

```
用户请求 (开始)
    ↓ [耗时: 50ms]
规划模块: "需要先查订单"
    ↓ [耗时: 1.2s]
工具调用: 订单API (成功, 返回订单号)
    ↓ [耗时: 800ms]
工具调用: 退款API (成功)
    ↓ [耗时: 30ms]
生成回复: "已为您退款"
```

这就是OTel的核心能力——让你**看到系统内部的全貌**。

## 二、OTel的三大支柱

| 类型               | 说明                                   | 类比                                        |
| ------------------ | -------------------------------------- | ------------------------------------------- |
| **Trace（链路）**  | 记录一次完整请求的调用路径和耗时       | 外卖订单的完整处理流程：接单→备餐→配送→送达 |
| **Metric（指标）** | 统计数据的聚合值（成功率、平均耗时等） | 每天有多少订单、平均配送时长                |
| **Log（日志）**    | 离散的事件记录                         | “用户12345申请退款，订单号67890”            |

OTel的巧妙之处在于，它把这三种数据**关联起来**：你可以从Metric发现“退款成功率下降”，钻进去看到具体哪个Trace失败了，再查看对应的Log找到错误堆栈。

## 三、在Go Agent中的典型使用

```go
import (
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/attribute"
)

// 在关键步骤创建Span（追踪段）
func (a *Agent) ProcessRequest(ctx context.Context, req Request) error {
    // 开始一个追踪段
    ctx, span := otel.Tracer("agent").Start(ctx, "ProcessRequest")
    defer span.End()

    // 规划阶段
    span.AddEvent("开始规划")
    plan := a.Plan(req)

    // 调用工具
    for _, tool := range plan.Tools {
        result, err := a.CallTool(ctx, tool)
        if err != nil {
            // 记录错误属性
            span.RecordError(err)
            span.SetAttributes(attribute.Bool("success", false))
            return err
        }
    }

    span.SetAttributes(attribute.Int("tools_called", len(plan.Tools)))
    return nil
}
```

这段代码会让Agent的每一步都自动上报，在Grafana中就能看到完整的执行链路。

## 四、OTel解决了Agent开发的特殊痛点

AI Agent相比传统服务，更难调试，因为：

| 痛点           | OTel如何解决                                |
| -------------- | ------------------------------------------- |
| **非确定性**   | 每次执行路径不同，OTel能记录实际的执行分支  |
| **多轮循环**   | 可以看到Agent在“思考-调用-反思”中循环了几次 |
| **工具调用链** | 清晰展示Agent调了哪些工具、谁依赖谁         |
| **Token消耗**  | 可以在Span中记录每次LLM调用的token数        |
| **成本归因**   | 统计每个用户/每个会话消耗了多少token和时长  |

## 五、和Python原型阶段的对应关系

| 阶段           | 可视化方式                    | 作用                   |
| -------------- | ----------------------------- | ---------------------- |
| **Python原型** | Jupyter Notebook + Matplotlib | 快速调试，看流程对不对 |
| **Go生产**     | OTel + Grafana                | 24/7监控，看性能稳不稳 |

你在Python阶段用Matplotlib画的是“一次运行的快照”，在生产环境用OTel + Grafana看到的是“持续运行的实况”。

## 六、快速上手路径

如果要在Go项目中接入OTel，典型流程是：

1. **代码埋点**：在关键位置创建Span，记录属性和事件
2. **配置导出**：将数据发送到Collector或直接发给后端
3. **对接后端**：使用Grafana Tempo（链路）、Prometheus（指标）、Loki（日志）
4. **构建看板**：在Grafana中创建仪表盘，可视化Agent的实时状态

对于Go生态，`otel`库的支持非常成熟，接入成本并不高。

---

## 七、总结

**OpenTelemetry = 为你的Agent装上“透视镜”**

- **Trace**：看到一次请求的完整路径
- **Metric**：统计整体健康度
- **Log**：记录细节信息

在AI Agent这种复杂、非确定性的系统中，OTel已经从“可选”变成了“必需”。它让你在生产环境也能获得类似Python原型阶段的调试体验，只是图表更专业、数据更实时。
