# 🎯 核心总结

## **抽象类 vs 接口**

| 方面     | **抽象类**         | **接口**                                     |
| -------- | ------------------ | -------------------------------------------- |
| **核心** | "是什么"（IS-A）   | "能做什么"（CAN-DO）                         |
| **继承** | 单继承             | 多实现                                       |
| **状态** | 可有字段、构造函数 | 无实例字段、无构造函数                       |
| **成员** | 完整实现+抽象成员  | C# 8.0前：只有声明<br>C# 8.0后：可有默认实现 |
| **设计** | 共享代码和状态     | 定义契约和能力                               |

---

## **C# 8.0接口默认实现的真相**

❌ **不能完全替代抽象类**，因为：

1. **无状态存储**：接口不能有实例字段
2. **无构造函数**：无法控制初始化
3. **访问控制有限**：无法完全封装
4. **语义不同**：接口是契约，抽象类是类型定义

✅ **接口默认实现主要用于**：

- API向后兼容
- 减少重复代码
- Mixin模式支持

---

## **选择指南**

**用抽象类当**：

- 需要共享代码/状态
- 需要构造函数初始化
- 严格的"IS-A"关系
- 模板方法模式

**用接口当**：

- 需要多继承
- 定义跨类型能力
- 依赖注入/测试
- 插件架构
- 向后兼容API设计

**一句话原则**：抽象类定义**是什么**，接口定义**能做什么**。两者互补，各司其职。
