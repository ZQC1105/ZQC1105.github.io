# 🔄 async/await 工作原理

**核心**：编译器将async方法转为**状态机**，在遇到`await`时：

- 如果任务未完成 → **暂停方法**，**返回控制权**给调用者
- 任务完成后 → **回调恢复**执行
- **不创建线程**，只是高效利用现有线程

---

# 🎯 "async不一定在新线程中运行"的原因

1. **I/O操作**：使用I/O完成端口，**无线程等待**（如文件读写、网络请求）
2. **已完成的Task**：直接同步执行，**不切换线程**
3. **CPU密集型任务**：才可能用线程池线程并行执行

**本质区别**：

- **多线程**：创建新线程（资源开销）
- **异步**：非阻塞等待（高效利用）

---

# ⚠️ UI线程使用注意事项

## **❌ 禁止行为**

1. **不要用`.Result`/`.Wait()`** → 可能导致死锁
2. **不要随意用`async void`** → 只用于事件处理器
3. **不要忘记异常处理** → async void中异常会崩溃应用

## **✅ 必须遵守**

1. **全程async/await**，不混合阻塞调用
2. **默认await后回UI线程**，进行UI更新
3. **不需要UI上下文时**用`ConfigureAwait(false)`
4. **支持取消**：传递`CancellationToken`
5. **用`Task.WhenAll`**优化多个异步操作

---

# 💡 关键要点

**async/await ≠ 多线程**，而是**非阻塞等待模型**。在UI线程中正确使用时能提升响应性，错误使用则会导致死锁或界面冻结。**让UI线程只做UI工作，耗时操作交给异步**。
