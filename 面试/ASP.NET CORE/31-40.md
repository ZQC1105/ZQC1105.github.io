## 31. 如何在 Minimal API 中注入依赖？

Minimal API 支持多种依赖注入方式：

**方法一：通过参数注入（最常用）**

```csharp
// 注册服务
builder.Services.AddScoped<IProductService, ProductService>();
builder.Services.AddSingleton<ICacheService, RedisCacheService>();

// 在 MapGet 委托参数中直接注入
app.MapGet("/products", async (IProductService productService) =>
{
    return await productService.GetAllAsync();
});

app.MapGet("/products/{id}", async (int id, IProductService productService, ICacheService cache) =>
{
    var cached = await cache.GetAsync($"product:{id}");
    if (cached != null) return cached;

    var product = await productService.GetByIdAsync(id);
    await cache.SetAsync($"product:{id}", product);
    return product;
});
```

**方法二：通过 HttpContext 获取**

```csharp
app.MapGet("/orders", async (HttpContext context) =>
{
    var orderService = context.RequestServices.GetRequiredService<IOrderService>();
    return await orderService.GetOrdersAsync();
});
```

**方法三：通过扩展方法注入多个服务**

```csharp
app.MapGet("/complex", async (
    IProductService productService,
    IOrderService orderService,
    IUserService userService,
    ILogger<Program> logger) =>
{
    logger.LogInformation("Processing complex request");
    var products = await productService.GetAllAsync();
    var orders = await orderService.GetOrdersAsync();
    return Results.Ok(new { products, orders });
});
```

**方法四：绑定到自定义类型（使用 AsParameters）**

```csharp
public record ProductRequestHandlers(
    IProductService ProductService,
    IOrderService OrderService,
    ILogger<ProductRequestHandlers> Logger);

app.MapGet("/products-with-handlers", ([AsParameters] ProductRequestHandlers handlers) =>
{
    handlers.Logger.LogInformation("Using AsParameters");
    return handlers.ProductService.GetAllAsync();
});
```

## 33. 什么是 Output Caching？

**Output Caching** 是 ASP.NET Core 7+ 引入的功能，用于**缓存整个 HTTP 响应**（包括状态码、Headers 和 Body），当相同请求再次到达时，直接从缓存返回，不执行端点逻辑。

**核心特点**：

- 缓存整个响应（比 Response Caching 更强大）
- 支持 Vary by Header、Query String 等
- 支持缓存驱逐和过期策略
- 需要**幂等请求**（GET、HEAD）

**启用 Output Caching**：

```csharp
// 1. 注册服务
builder.Services.AddOutputCache(options =>
{
    options.AddBasePolicy(builder => builder.Expire(TimeSpan.FromMinutes(5)));
    options.AddPolicy("ShortCache", builder => builder.Expire(TimeSpan.FromSeconds(30)));
    options.AddPolicy("LongCache", builder => builder.Expire(TimeSpan.FromHours(1))
        .SetVaryByQuery("page", "size"));
});

// 2. 使用中间件
app.UseOutputCache();

// 3. 应用到端点
app.MapGet("/slow-data", async () =>
{
    await Task.Delay(1000);  // 模拟耗时操作
    return new { data = "expensive response", timestamp = DateTime.UtcNow };
}).CacheOutput();  // 使用默认策略

app.MapGet("/products", () => GetProducts())
   .CacheOutput(policy => policy.Expire(TimeSpan.FromMinutes(10))
                                .Tag("products"));  // 支持标签驱逐

app.MapGet("/search", (string q, int page) => Search(q, page))
   .CacheOutput(policy => policy.SetVaryByQuery("q", "page")
                                .Expire(TimeSpan.FromMinutes(5)));
```

**缓存变体（Vary）示例**：

```csharp
// 根据 Accept-Language 头缓存不同版本
app.MapGet("/greeting", () => "Hello")
   .CacheOutput(policy => policy.SetVaryByHeader("Accept-Language"));

// 根据认证状态缓存（匿名用户 vs 登录用户）
app.MapGet("/profile", (ClaimsPrincipal user) => GetProfile(user))
   .CacheOutput(policy => policy.SetVaryByHeader("Authorization"));
```

## 34. IMemoryCache 和 IDistributedCache 的区别

| 特性           | IMemoryCache                 | IDistributedCache                     |
| -------------- | ---------------------------- | ------------------------------------- |
| **存储位置**   | 应用程序**内存**（单机）     | 外部存储（Redis、SQL Server、NCache） |
| **适用范围**   | 单服务器部署                 | 多服务器、负载均衡、Kubernetes 集群   |
| **性能**       | 极快（纳秒级）               | 较慢（网络 I/O，毫秒级）              |
| **数据持久化** | 应用重启后丢失               | 数据持久化，跨重启保留                |
| **容量**       | 受限于服务器内存             | 可扩展（分布式缓存集群）              |
| **过期机制**   | 支持绝对/滑动过期            | 支持绝对/滑动过期                     |
| **典型场景**   | 单机应用、频繁访问的配置数据 | 共享 Session、多服务器缓存一致性      |

**IMemoryCache 示例**：

```csharp
builder.Services.AddMemoryCache();

public class ProductService
{
    private readonly IMemoryCache _cache;

    public async Task<Product> GetProductAsync(int id)
    {
        var cacheKey = $"product_{id}";

        return await _cache.GetOrCreateAsync(cacheKey, async entry =>
        {
            entry.SlidingExpiration = TimeSpan.FromMinutes(5);
            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(1);

            return await _db.Products.FindAsync(id);
        });
    }
}
```

**IDistributedCache 示例（Redis）**：

```csharp
// 安装: dotnet add package Microsoft.Extensions.Caching.StackExchangeRedis
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "localhost:6379";
    options.InstanceName = "MyApp_";
});

public class ProductService
{
    private readonly IDistributedCache _cache;

    public async Task<Product> GetProductAsync(int id)
    {
        var cacheKey = $"product_{id}";
        var cached = await _cache.GetStringAsync(cacheKey);

        if (cached != null)
            return JsonSerializer.Deserialize<Product>(cached);

        var product = await _db.Products.FindAsync(id);

        var options = new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(1),
            SlidingExpiration = TimeSpan.FromMinutes(5)
        };

        await _cache.SetStringAsync(cacheKey, JsonSerializer.Serialize(product), options);

        return product;
    }
}
```

## 35. 解释 HybridCache / FusionCache 的工作原理

**HybridCache**（.NET 9 预览版引入）和 **FusionCache**（第三方库）都是**混合缓存**解决方案，结合了 L1（内存缓存）和 L2（分布式缓存）的优点。

**工作原理**：

```
读操作流程：
1. 检查 L1 内存缓存（极快）
2. 如果未命中，检查 L2 分布式缓存（如 Redis）
3. 如果仍未命中，从数据源加载
4. 同时写入 L1 和 L2

写操作/失效流程：
- 立即更新/删除 L1 和 L2 中的相关数据
- 或使用消息总线通知其他节点的 L1 失效
```

**FusionCache 示例**：

```csharp
// 安装: dotnet add package ZiggyCreatures.FusionCache

builder.Services.AddFusionCache()
    .WithDefaultEntryOptions(new FusionCacheEntryOptions
    {
        Duration = TimeSpan.FromMinutes(5),
        IsFailSafeEnabled = true,  // 数据源失败时返回过期的缓存
        FailSafeMaxDuration = TimeSpan.FromHours(2)
    })
    .WithSerializer(new FusionCacheSystemTextJsonSerializer())
    .WithDistributedCache(new FusionCacheRedisCache(redisConnection));

public class ProductService
{
    private readonly IFusionCache _cache;

    public async Task<Product> GetProductAsync(int id)
    {
        return await _cache.GetOrSetAsync(
            $"product:{id}",
            async ct => await _db.Products.FindAsync(id),
            tag: "products"  // 支持标签批量失效
        );
    }

    public async Task InvalidateProductsAsync()
    {
        await _cache.RemoveByTagAsync("products");
    }
}
```

**HybridCache 概念示例**（.NET 9 Preview）：

```csharp
// 预览版 API 可能变化
builder.Services.AddHybridCache();

public class ProductService
{
    private readonly IHybridCache _cache;

    public async Task<Product> GetProductAsync(int id, CancellationToken token)
    {
        return await _cache.GetOrCreateAsync(
            $"product:{id}",
            async cancel => await _db.Products.FindAsync(id),
            new HybridCacheEntryOptions
            {
                Expiration = TimeSpan.FromMinutes(5),
                LocalCacheExpiration = TimeSpan.FromSeconds(30)  // L1 更短，L2 更长
            },
            token
        );
    }
}
```

**优势**：

- **性能**：L1 命中时微秒级响应
- **一致性**：L1 和 L2 自动同步
- **可靠性**：数据源故障时可返回过期缓存（防崩溃）
- **效率**：减少对 L2 的请求

## 36. 你知道哪些缓存模式？

| 模式                           | 描述                                       | 适用场景             |
| ------------------------------ | ------------------------------------------ | -------------------- |
| **Cache-Aside**（旁路缓存）    | 应用先查缓存，未命中则查数据库并写入缓存   | 最常见模式，读多写少 |
| **Read-Through**（通读）       | 缓存组件负责从数据源读取，应用只与缓存交互 | 统一缓存抽象层       |
| **Write-Through**（通写）      | 写入时同时更新缓存和数据源                 | 需要强一致性         |
| **Write-Behind**（后写）       | 先写缓存，异步批量写入数据库               | 高吞吐写入场景       |
| **Refresh-Ahead**（预刷新）    | 在缓存过期前异步刷新                       | 热点数据持续访问     |
| **Cache Invalidation**（失效） | 数据更新时主动删除缓存                     | 保证数据新鲜度       |

**Cache-Aside 模式（最常用）**：

```csharp
public async Task<Product> GetProductAsync(int id)
{
    // 1. 查缓存
    var product = await _cache.GetAsync<Product>($"product:{id}");
    if (product != null) return product;

    // 2. 查数据库
    product = await _db.Products.FindAsync(id);

    // 3. 写缓存
    await _cache.SetAsync($"product:{id}", product);

    return product;
}
```

**Write-Behind 模式**：

```csharp
public class WriteBehindService
{
    private readonly BlockingCollection<WriteOperation> _queue = new();

    public WriteBehindService()
    {
        Task.Run(ProcessQueueAsync);
    }

    public async Task WriteAsync(string key, object value)
    {
        await _cache.SetAsync(key, value);  // 立即写缓存
        _queue.Add(new WriteOperation(key, value));  // 加入队列
    }

    private async Task ProcessQueueAsync()
    {
        await foreach (var op in _queue.GetConsumingEnumerable())
        {
            await _db.SaveAsync(op.Key, op.Value);  // 批量写数据库
        }
    }
}
```

## 37. Rate Limiting 的作用和类型

**Rate Limiting（速率限制）** 用于控制客户端在特定时间窗口内可发起的请求数量，防止 API 被滥用、DDoS 攻击或资源耗尽。

**作用**：

- 防止暴力破解
- 保证服务公平性
- 控制成本和资源消耗
- 抵御 DoS 攻击

**ASP.NET Core 内置的限流类型（.NET 7+）**：

| 类型               | 算法     | 说明                                                    |
| ------------------ | -------- | ------------------------------------------------------- |
| **Fixed Window**   | 固定窗口 | 固定时间窗口（如每分钟最多 100 次），窗口重置时计数归零 |
| **Sliding Window** | 滑动窗口 | 按秒分割的更精细控制，避免窗口边界突发                  |
| **Token Bucket**   | 令牌桶   | 以恒定速率填充令牌，每个请求消耗一个令牌，允许突发      |
| **Concurrency**    | 并发限制 | 限制同时处理的请求数（如同时最多 10 个）                |

**示例实现**：

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(
        httpContext => RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: httpContext.User.Identity?.Name ?? httpContext.Request.Headers.Host.ToString(),
            factory: partition => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 100,
                Window = TimeSpan.FromMinutes(1),
                QueueProcessingOrder = QueueProcessingOrder.OldestFirst,
                QueueLimit = 5
            }
        ));

    // 添加特定策略
    options.AddPolicy("LoginPolicy", httpContext =>
        RateLimitPartition.GetSlidingWindowLimiter("login",
            _ => new SlidingWindowRateLimiterOptions
            {
                PermitLimit = 5,
                Window = TimeSpan.FromMinutes(1),
                SegmentsPerWindow = 6  // 分成 6 个 10 秒的段
            }));

    options.AddPolicy("ApiPolicy", httpContext =>
        RateLimitPartition.GetTokenBucketLimiter("api",
            _ => new TokenBucketRateLimiterOptions
            {
                TokenLimit = 100,
                TokensPerPeriod = 10,
                ReplenishmentPeriod = TimeSpan.FromSeconds(1),
                AutoReplenishment = true
            }));

    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
});

app.UseRateLimiter();

// 应用到端点
app.MapGet("/public", () => "Public").RequireRateLimiting("LoginPolicy");
app.MapGet("/api", () => "API").RequireRateLimiting("ApiPolicy");
app.MapGet("/default", () => "Default");  // 使用全局策略

// 禁用限流
app.MapGet("/unlimited", () => "No limit").DisableRateLimiting();
```

## 38. 如何使 OutputCache 中的数据失效？

**方法一：通过 Tag 批量失效**

```csharp
// 缓存时添加 Tag
app.MapGet("/products", () => GetAllProducts())
   .CacheOutput(policy => policy.Tag("products"));

app.MapGet("/product/{id}", (int id) => GetProduct(id))
   .CacheOutput(policy => policy.Tag("products", $"product:{id}"));

// 失效时通过 IOutputCacheStore
app.MapPost("/products", async (Product product, IOutputCacheStore cache) =>
{
    await _service.CreateAsync(product);
    await cache.EvictByTagAsync("products", CancellationToken.None);  // 清除所有 products 标签缓存
    return Results.Created();
});

app.MapPut("/product/{id}", async (int id, Product product, IOutputCacheStore cache) =>
{
    await _service.UpdateAsync(id, product);
    await cache.EvictByTagAsync($"product:{id}", CancellationToken.None);
    return Results.Ok();
});
```

**方法二：通过 Policy 名称失效**

```csharp
app.MapGet("/dashboard", GetDashboard)
   .CacheOutput("DashboardPolicy");

// 清除特定策略的缓存
await cache.EvictByTagAsync("DashboardPolicy", CancellationToken.None);
```

**方法三：基于依赖变化自动失效**

```csharp
public class ProductService
{
    private readonly IOutputCacheStore _cache;
    private readonly IMediator _mediator;

    public ProductService(IOutputCacheStore cache, IMediator mediator)
    {
        _cache = cache;
        _mediator = mediator;
    }

    public async Task UpdateProduct(Product product)
    {
        await _db.SaveChangesAsync();

        // 发布领域事件
        await _mediator.Publish(new ProductUpdatedEvent(product.Id));
    }
}

// 事件处理器自动失效缓存
public class ProductUpdatedHandler : INotificationHandler<ProductUpdatedEvent>
{
    private readonly IOutputCacheStore _cache;

    public async Task Handle(ProductUpdatedEvent notification, CancellationToken ct)
    {
        await _cache.EvictByTagAsync($"product:{notification.ProductId}", ct);
        await _cache.EvictByTagAsync("products", ct);
    }
}
```

**方法四：基于时间自动过期**

```csharp
// 绝对过期
app.MapGet("/time-sensitive", () => GetData())
   .CacheOutput(policy => policy.Expire(TimeSpan.FromSeconds(30)));

// 滑动过期
app.MapGet("/session-data", () => GetSessionData())
   .CacheOutput(policy => policy.SetSlidingExpiration(TimeSpan.FromMinutes(5)));
```

## 39. 如何实现 API 版本控制？

**使用 Asp.Versioning.Mvc（推荐）**

```csharp
// 安装: dotnet add package Asp.Versioning.Mvc

builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.AssumeDefaultVersionWhenUnspecified = true;
    options.ReportApiVersions = true;  // 响应头返回支持的版本
    options.ApiVersionReader = ApiVersionReader.Combine(
        new UrlSegmentApiVersionReader(),      // URL 路径
        new QueryStringApiVersionReader("api-version"),  // 查询参数
        new HeaderApiVersionReader("X-API-Version"),     // 请求头
        new MediaTypeApiVersionReader()        // Content-Type
    );
}).AddMvc().AddApiExplorer();
```

**版本控制方式示例**：

```csharp
// 方式1：URL 路径版本（最常用）
[ApiController]
[Route("api/v{version:apiVersion}/[controller]")]
public class ProductsController : ControllerBase
{
    [MapToApiVersion(1.0)]
    [HttpGet]
    public IActionResult GetV1() => Ok(new { version = "1.0", name = "Product V1" });

    [MapToApiVersion(2.0)]
    [HttpGet]
    public IActionResult GetV2() => Ok(new { version = "2.0", name = "Product V2", price = 100 });
}

// 方式2：查询字符串
// GET /api/products?api-version=1.0
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet, MapToApiVersion(1.0)]
    public IActionResult GetV1() => Ok("V1");

    [HttpGet, MapToApiVersion(2.0)]
    public IActionResult GetV2() => Ok("V2");
}

// 方式3：请求头版本
// 请求头: X-API-Version: 2.0
builder.Services.AddApiVersioning(options =>
{
    options.ApiVersionReader = new HeaderApiVersionReader("X-API-Version");
});

// 方式4：媒体类型版本
// Accept: application/json;version=2.0
builder.Services.AddApiVersioning(options =>
{
    options.ApiVersionReader = new MediaTypeApiVersionReader("version");
});
```

**Minimal API 版本控制**：

```csharp
// 安装: dotnet add package Asp.Versioning.Http

builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.ApiVersionReader = new UrlSegmentApiVersionReader();
}).AddApiExplorer();

var app = builder.Build();

var apiVersionSet = app.NewApiVersionSet()
    .HasApiVersion(new ApiVersion(1, 0))
    .HasApiVersion(new ApiVersion(2, 0))
    .ReportApiVersions()
    .Build();

app.MapGet("/api/v{version:apiVersion}/products", (ApiVersion version) =>
{
    return version.MajorVersion == 1
        ? Results.Ok(new { version = "1.0" })
        : Results.Ok(new { version = "2.0", newField = "added" });
}).WithApiVersionSet(apiVersionSet).MapToApiVersion(1.0, 2.0);
```

## 40. 如何在不改变 API URL 的情况下添加 API 版本控制？

当不能改变 URL 时（如 `/api/products` 保持原样），使用**查询参数、请求头或 Accept Header** 进行版本区分：

**方案一：查询字符串版本（最简单）**

```csharp
builder.Services.AddApiVersioning(options =>
{

    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.AssumeDefaultVersionWhenUnspecified = true;

[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet, MapToApiVersion(1.0)]
    public IActionResult GetV1() => Ok(new { version = 1 });

    [HttpGet, MapToApiVersion(2.0)]
    public IActionResult GetV2() => Ok(new { version = 2, extra = "data" });
}
// 请求: GET /api/products?v=2.0
```

**方案二：请求头版本**

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.ApiVersionReader = new HeaderApiVersionReader("X-API-Version");

// 请求头: X-API-Version: 2.0
```

```csharp

// Accept: application/json;version=2.0
```

**方案四：自定义版本解析器（同时支持多种方式）**

```csharp
public class CustomApiVersionReader : IApiVersionReader
{
    public void Read(ApiVersionReaderContext context)
    {
        // 优先级: Header > Query > Default
        if (context.Request.Headers.TryGetValue("X-API-Version", out var headerVersion))
            context.ApiVersion = ApiVersion.Parse(headerVersion);
        else if (context.Request.Query.TryGetValue("v", out var queryVersion))
            context.ApiVersion = ApiVersion.Parse(queryVersion);
        else
            context.ApiVersion = new ApiVersion(1, 0);
    }
}

// 注册
builder.Services.AddApiVersioning(options =>
{
    options.ApiVersionReader = new CustomApiVersionReader();
});
```

**方案五：使用 Action 约束（不依赖 Asp.Versioning）**

```csharp
// 手动实现版本选择
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult Get()
    {
        var version = Request.Headers["X-API-Version"].FirstOrDefault() ?? "1.0";

        if (version == "2.0")
            return Ok(new { version = 2, data = "V2 response" });

        return Ok(new { version = 1, data = "V1 response" });
    }
}
```

**推荐方案**：使用 **HeaderApiVersionReader** + 保留原有 URL 结构，对现有客户端完全透明。
