在ASP.NET Core中，依赖注入（DI）的核心是围绕三种服务生命周期（Lifetime）展开的。框架本身并没有多种“注入方式”，而是提供了三种不同的**服务注册方式**，通过它们来控制实例的创建和销毁时机。

这三种生命周期的区别，直接决定了你的应用在性能、资源占用和线程安全方面的表现。

### 📌 三种服务生命周期详解

| 生命周期             | 注册方法            | 实例创建时机                                                                      | 共享范围               | 适用场景                                                                                     |
| :------------------- | :------------------ | :-------------------------------------------------------------------------------- | :--------------------- | :------------------------------------------------------------------------------------------- |
| **瞬时 (Transient)** | `AddTransient<T>()` | 每次从DI容器中请求时，都会创建一个**全新的实例**。                                | 不共享，每次都是新的。 | 轻量级、无状态的工具类服务。                                                                 |
| **作用域 (Scoped)**  | `AddScoped<T>()`    | 在每个作用域内只创建一个实例。对于Web应用，**每个HTTP请求就是一个独立的作用域**。 | 在同一HTTP请求中共享。 | 数据库上下文（`DbContext`）、工作单元模式（UnitOfWork）。**这是Web应用中最常用的生命周期**。 |
| **单例 (Singleton)** | `AddSingleton<T>()` | 在应用第一次请求时（或启动时）创建，之后**整个应用生命周期内都只有一个实例**。    | 全局共享。             | 全局配置、日志服务、内存缓存（`IMemoryCache`）等无状态的、需要复用的服务。                   |

### 🛠️ 如何使用：三步实现依赖注入

使用DI非常简单，主要遵循“定义 -> 注册 -> 使用”三个步骤。

#### 1. 定义服务接口和实现

为了解耦，通常建议定义一个接口，然后让具体类实现它。

```csharp
// 1. 定义接口
public interface IGreetingService
{
    string SayHello();
}

// 2. 实现接口
public class GreetingService : IGreetingService
{
    public string SayHello()
    {
        return "Hello from DI!";
    }
}
```

#### 2. 在容器中注册服务

在应用程序的启动入口（对于.NET 6+，通常在`Program.cs`文件）的`IServiceCollection`中注册服务。

```csharp
var builder = WebApplication.CreateBuilder(args);

// 将服务按照所需生命周期进行注册
builder.Services.AddTransient<IGreetingService, GreetingService>(); // 瞬时
builder.Services.AddScoped<IUserRepository, UserRepository>();       // 作用域
builder.Services.AddSingleton<ICacheService, InMemoryCache>();      // 单例

builder.Services.AddControllers();
var app = builder.Build();

// ... 其他配置
```

#### 3. 在控制器或类中注入并使用

通过构造函数注入的方式，将依赖的服务作为参数传入。DI容器会自动为你创建并传递所需服务的实例。

```csharp
// 在API控制器中
[ApiController]
[Route("api/[controller]")]
public class HomeController : ControllerBase
{
    private readonly IGreetingService _greetingService;
    private readonly IUserRepository _userRepository;

    // 构造函数注入：框架会自动提供GreetingService和UserRepository的实例
    public HomeController(IGreetingService greetingService, IUserRepository userRepository)
    {
        _greetingService = greetingService;
        _userRepository = userRepository;
    }

    [HttpGet]
    public IActionResult Get()
    {
        var message = _greetingService.SayHello();
        // ... 使用 _userRepository 进行数据库操作
        return Ok(message);
    }
}
```

### ⚠️ 关键注意事项

1.  **避免“向上”依赖**：一个生命周期较长的服务，**绝不应该依赖生命周期较短的服务**。例如：
    *   ❌ **错误**：一个单例（Singleton）服务，依赖一个作用域（Scoped）服务。
    *   因为单例服务是全局的，而作用域服务在请求结束后会被释放。如果单例持有它的引用，可能导致内存泄漏或其他不可预知的问题。ASP.NET Core在检测到这种“向上”依赖时，会在开发环境中抛出异常。

2.  **选型口诀**：快速决定使用哪种生命周期。
    *   **需要全局唯一、跨请求复用** → **单例（Singleton）**
    *   **需要在一次请求内共享状态、保持数据一致性（如数据库操作）** → **作用域（Scoped）**
    *   **服务轻量、无状态、每次都需要全新的实例** → **瞬时（Transient）**

### 🚀 进阶使用

*   **作用域（Scoped）不仅仅是Web请求**：虽然ASP.NET Core为每个HTTP请求自动创建一个作用域，但在后台任务、控制台应用或Worker Service中，你也可以手动创建作用域。
    ```csharp
    using (var scope = serviceProvider.CreateScope())
    {
        var dbContext = scope.ServiceProvider.GetRequiredService<MyDbContext>();
        // 在这个using块内，从scope获取的Scoped服务都是同一个实例
    }
    ```

*   **简化批量注册**：当项目庞大时，手动为每个服务写一行注册代码会变得繁琐。可以使用`Scrutor`这类开源库，通过扫描程序集来自动批量注册服务，大大提高效率。
