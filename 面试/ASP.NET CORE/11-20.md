## 11. 说出几种从 appsettings.json 读取数据的方法

**方法一：IConfiguration 直接读取**

```csharp
public class HomeController : Controller
{
    private readonly IConfiguration _config;
    public HomeController(IConfiguration config) => _config = config;

    public IActionResult Index()
    {
        var value = _config["MyKey"];                           // 简单键
        var nested = _config["MySection:SubKey"];              // 嵌套，使用冒号
        var connectionString = _config.GetConnectionString("Default");
        return View();
    }
}
```

**方法二：GetValue 泛型方法**

```csharp
int timeout = _config.GetValue<int>("Timeout", 30);
bool enabled = _config.GetValue<bool>("FeatureEnabled");
```

**方法三：GetSection + Bind 到强类型对象**

```csharp
// 定义类
public class EmailSettings
{
    public string SmtpServer { get; set; }
    public int Port { get; set; }
}

// 读取
var emailSettings = new EmailSettings();
_config.GetSection("EmailSettings").Bind(emailSettings);
// 或更简洁
var emailSettings = _config.GetSection("EmailSettings").Get<EmailSettings>();
```

**方法四：使用 Options 模式（推荐）**

```csharp
builder.Services.Configure<EmailSettings>(builder.Configuration.GetSection("EmailSettings"));
// 然后在需要的地方注入 IOptions<EmailSettings>
```

## 12. 什么是 Options 模式？

**Options 模式** 是 ASP.NET Core 中用于读取和管理配置的推荐方式，它将配置绑定到强类型类，并提供依赖注入支持。

**核心特点**：

- 将配置分组到有意义的类中
- 支持配置验证
- 支持配置热重载
- 分离配置定义和使用

**基本用法**：

```csharp
// 1. 定义 Options 类
public class EmailOptions
{
    public const string SectionName = "Email";
    public string SmtpServer { get; set; } = string.Empty;
    public int Port { get; set; } = 25;
    public bool UseSsl { get; set; }
}

// 2. 注册配置
builder.Services.Configure<EmailOptions>(
    builder.Configuration.GetSection(EmailOptions.SectionName));

// 3. 注入使用
public class EmailService
{
    private readonly EmailOptions _options;

    public EmailService(IOptions<EmailOptions> options)
    {
        _options = options.Value;
    }
}
```

## 13. IOptionsSnapshot 和 IOptionsMonitor 的使用场景

| 接口                      | 特点                                                  | 适用场景                                                        |
| ------------------------- | ----------------------------------------------------- | --------------------------------------------------------------- |
| **IOptions\<T\>**         | 单例，配置加载后**永不更新**                          | 应用启动后不再变化的静态配置                                    |
| **IOptionsSnapshot\<T\>** | Scoped 生命周期，每次请求**重新读取**配置，支持热重载 | 需要感知配置变化的场景，但**仅适用于 Scoped 或 Transient 服务** |
| **IOptionsMonitor\<T\>**  | 单例，支持**配置变更通知**和热重载                    | Singleton 服务、需要实时响应配置变化的场景                      |

**示例**：

```csharp
// 使用 IOptionsMonitor - 可以监听变化
public class MonitorService : IHostedService
{
    private readonly IOptionsMonitor<EmailOptions> _monitor;
    private IDisposable? _changeToken;

    public MonitorService(IOptionsMonitor<EmailOptions> monitor)
    {
        _monitor = monitor;
        _changeToken = _monitor.OnChange(options =>
        {
            Console.WriteLine($"配置已更新: {options.SmtpServer}");
        });
    }
}

// 使用 IOptionsSnapshot - 每次请求获取最新值
public class EmailService
{
    public EmailService(IOptionsSnapshot<EmailOptions> options)
    {
        var latestConfig = options.Value; // 每次请求重新读取
    }
}
```

## 14. 如何验证配置？

**方法一：DataAnnotations 验证**

```csharp
public class EmailOptions
{
    [Required]
    [MinLength(5)]
    public string SmtpServer { get; set; }

    [Range(1, 65535)]
    public int Port { get; set; }
}

// 注册时添加验证
builder.Services.AddOptions<EmailOptions>()
    .Bind(builder.Configuration.GetSection("Email"))
    .ValidateDataAnnotations()
    .ValidateOnStart();  // 启动时立即验证
```

**方法二：自定义验证函数**

```csharp
builder.Services.AddOptions<EmailOptions>()
    .Bind(config.GetSection("Email"))
    .Validate(options => options.Port != 25 || !options.UseSsl,
              "端口25不支持SSL")
    .ValidateOnStart();
```

**方法三：实现 IValidateOptions\<T\>**

```csharp
public class EmailValidation : IValidateOptions<EmailOptions>
{
    public ValidateOptionsResult Validate(string? name, EmailOptions options)
    {
        if (string.IsNullOrEmpty(options.SmtpServer))
            return ValidateOptionsResult.Fail("SmtpServer不能为空");
        return ValidateOptionsResult.Success;
    }
}
```

## 15. DataAnnotations 和 FluentValidation 的区别

| 特性           | DataAnnotations                  | FluentValidation                 |
| -------------- | -------------------------------- | -------------------------------- |
| **定义位置**   | 通过**特性**直接标记在模型类上   | 在独立的**验证器类**中定义规则   |
| **模型污染**   | 会污染模型类（与验证逻辑耦合）   | 模型类保持纯净（关注点分离）     |
| **灵活性**     | 有限，复杂条件验证困难           | 极高，支持条件、级联、自定义规则 |
| **可重用性**   | 规则绑定在类上，难以复用         | 验证器可独立复用和组合           |
| **支持框架**   | 仅 .NET 原生                     | 可独立使用，支持多种框架         |
| **客户端验证** | 原生支持 ASP.NET Core 客户端验证 | 需要额外配置                     |
| **复杂场景**   | 需要复杂条件时代码冗长           | `When()`、`Must()` 等简洁优雅    |

**DataAnnotations 示例**：

```csharp
public class User
{
    [Required]
    [EmailAddress]
    [StringLength(100)]
    public string Email { get; set; }
}
```

**FluentValidation 示例**：

```csharp
public class UserValidator : AbstractValidator<User>
{
    public UserValidator()
    {
        RuleFor(x => x.Email)
            .NotEmpty().WithMessage("邮箱不能为空")
            .EmailAddress()
            .MaximumLength(100);

        RuleFor(x => x.Password)
            .Must((user, password) => password != user.Email)
            .WithMessage("密码不能与邮箱相同");
    }
}
```

## 16. 解释 Action Filter 以及在 Controller 中的使用方式

**Action Filter** 是一种用于在执行 Action 方法**前后**插入逻辑的过滤器，用于横切关注点（cross-cutting concerns）。

**常用场景**：

- 日志记录、性能监控
- 参数验证和转换
- 缓存控制
- 异常处理

**实现方式**：

```csharp
// 1. 自定义 Action Filter
public class LogActionFilter : IActionFilter
{
    private readonly ILogger<LogActionFilter> _logger;

    public void OnActionExecuting(ActionExecutingContext context)
    {
        // Action 执行前
        var actionName = context.ActionDescriptor.DisplayName;
        _logger.LogInformation($"开始执行: {actionName}");
    }

    public void OnActionExecuted(ActionExecutedContext context)
    {
        // Action 执行后
        if (context.Exception != null)
        {
            _logger.LogError(context.Exception, "执行失败");
        }
    }
}

// 2. 注册全局过滤器
builder.Services.AddControllers(options =>
{
    options.Filters.Add<LogActionFilter>();
});

// 3. 或应用到特定 Controller/Action
[ServiceFilter(typeof(LogActionFilter))]
public class ProductsController : ControllerBase
{
    [HttpGet]
    [LogActionFilter]  // 只应用到单个 Action
    public IActionResult Get() { ... }
}
```

**异步版本**：

```csharp
public class AsyncLogFilter : IAsyncActionFilter
{
    public async Task OnActionExecutionAsync(
        ActionExecutingContext context,
        ActionExecutionDelegate next)
    {
        // 执行前
        var result = await next();  // 执行 Action
        // 执行后
    }
}
```

## 17. 为什么 Minimal API 比 Controller 更快？

Minimal API 比传统 Controller 更快的主要原因：

| 因素           | Controller                            | Minimal API          | 性能差异原因           |
| -------------- | ------------------------------------- | -------------------- | ---------------------- |
| **反射开销**   | 每次请求需要反射来发现 Action 方法    | 委托直接调用         | Minimal API 避免了反射 |
| **中间件层级** | 经过 MVC 中间件（复杂路由、模型绑定） | 轻量级管道           | 处理链更短             |
| **对象分配**   | 为每个请求创建 Controller 实例        | 委托静态方法或无状态 | GC 压力更小            |
| **模型绑定**   | 复杂模型绑定系统                      | 简化的参数绑定       | 开销更低               |
| **过滤器管道** | 默认启用完整过滤器管道                | 无内置过滤器         | 跳过额外处理           |

**性能数据参考**（社区基准测试）：

- Minimal API 比 Controller API 快约 **30-40%**
- 内存分配减少约 **50-70%**

**示例对比**：

```csharp
// Controller - 较重
[ApiController]
[Route("api/[controller]")]
public class HelloController : ControllerBase
{
    [HttpGet]
    public string Get() => "Hello";
}

// Minimal API - 更轻量
app.MapGet("/api/hello", () => "Hello");
```

## 18. 如何为项目添加授权？

**步骤 1：添加认证服务**

```csharp
var builder = WebApplication.CreateBuilder(args);

// 添加认证（决定用户是谁）
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.Authority = "https://your-auth-server";
        options.Audience = "your-api";
    });
    // 或使用 Cookie 认证
    // .AddCookie(options => {...});

// 添加授权（决定用户能做什么）
builder.Services.AddAuthorization();
```

**步骤 2：添加中间件（顺序重要）**

```csharp
app.UseAuthentication();  // 先认证
app.UseAuthorization();   // 后授权
app.MapControllers();
```

**步骤 3：应用到端点**

```csharp
// 应用到所有 Controller
[Authorize]
public class SecureController : ControllerBase { }

// 应用到特定 Action
[HttpGet]
[Authorize(Roles = "Admin")]
public IActionResult AdminOnly() { }

// Minimal API 方式
app.MapGet("/secure", () => "Secure").RequireAuthorization();
```

## 19. 如何为所有 Controller 方法添加授权，但排除其中一个？

**方案一：全局过滤器 + AllowAnonymous**

```csharp
// 全局应用授权
builder.Services.AddControllers(options =>
{
    var policy = new AuthorizationPolicyBuilder()
        .RequireAuthenticatedUser()
        .Build();
    options.Filters.Add(new AuthorizeFilter(policy));
});

// 在需要公开的 Action 上添加 [AllowAnonymous]
[AllowAnonymous]
[HttpGet("public")]
public IActionResult Public() { }
```

**方案二：自定义默认授权策略**

```csharp
// 设置默认策略要求认证
builder.Services.AddAuthorization(options =>
{
    options.FallbackPolicy = new AuthorizationPolicyBuilder()
        .RequireAuthenticatedUser()
        .Build();
});

// 例外 Action 使用 [AllowAnonymous]
```

**方案三：Base Controller + 选择性覆盖**

```csharp
[Authorize]  // 基类要求认证
public abstract class BaseController : ControllerBase { }

public class HomeController : BaseController
{
    [AllowAnonymous]  // 覆盖基类
    public IActionResult PublicPage() { }

    public IActionResult PrivatePage() { }  // 继承认证要求
}
```

## 20. 如何实现登录功能？

**使用 Cookie 认证的登录实现**：

```csharp
// 1. 配置 Cookie 认证
builder.Services.AddAuthentication(CookieAuthenticationDefaults.AuthenticationScheme)
    .AddCookie(options =>
    {
        options.LoginPath = "/Account/Login";
        options.LogoutPath = "/Account/Logout";
        options.ExpireTimeSpan = TimeSpan.FromHours(8);
    });

// 2. 登录 Action
[HttpPost("login")]
public async Task<IActionResult> Login(LoginModel model)
{
    if (!ModelState.IsValid)
        return BadRequest(ModelState);

    // 验证用户凭证（示例：从数据库查询）
    var user = await _userService.ValidateUserAsync(model.Username, model.Password);

    if (user == null)
        return Unauthorized("用户名或密码错误");

    // 创建 Claims（用户身份信息）
    var claims = new List<Claim>
    {
        new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
        new Claim(ClaimTypes.Name, user.Username),
        new Claim(ClaimTypes.Email, user.Email),
        new Claim(ClaimTypes.Role, user.Role)
    };

    var claimsIdentity = new ClaimsIdentity(claims, CookieAuthenticationDefaults.AuthenticationScheme);
    var authProperties = new AuthenticationProperties
    {
        IsPersistent = model.RememberMe,  // 持久化 Cookie
        ExpiresUtc = DateTimeOffset.UtcNow.AddHours(8)
    };

    // 登录 - 签发 Cookie
    await HttpContext.SignInAsync(
        CookieAuthenticationDefaults.AuthenticationScheme,
        new ClaimsPrincipal(claimsIdentity),
        authProperties);

    return Ok(new { message = "登录成功", redirectUrl = "/" });
}

// 3. 登出
[HttpPost("logout")]
public async Task<IActionResult> Logout()
{
    await HttpContext.SignOutAsync(CookieAuthenticationDefaults.AuthenticationScheme);
    return Ok(new { message = "已登出" });
}

// 4. 获取当前用户信息
[HttpGet("me")]
[Authorize]
public IActionResult GetCurrentUser()
{
    var userId = User.FindFirstValue(ClaimTypes.NameIdentifier);
    var username = User.Identity?.Name;
    return Ok(new { userId, username });
}
```

**密码验证建议**：

- 使用 **BCrypt** 或 **PBKDF2** 存储哈希密码，不要明文存储
- 使用 **ASP.NET Core Identity** 框架可以获得完整的用户管理、密码重置、双因素认证等功能
