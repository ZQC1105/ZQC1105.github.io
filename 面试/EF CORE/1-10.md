以下是 Entity Framework Core 前 10 个问题的中文答案：

## 1. 什么是 EF Core 中的迁移（Migration）？

**迁移（Migration）** 是一种将数据模型的变化同步到数据库架构的机制，它通过代码记录模型的变更历史，并生成相应的 SQL 脚本来更新数据库。

**工作流程**：

```
1. 定义/修改实体类（如添加属性）
   ↓
2. 创建迁移：dotnet ef migrations add AddEmailToUser
   ↓ (生成三个文件)
   ├── {timestamp}_AddEmailToUser.cs (主迁移文件：Up/Down 方法)
   ├── {timestamp}_AddEmailToUser.Designer.cs (快照)
   └── MyContextModelSnapshot.cs (当前模型快照)
   ↓
3. 应用迁移：dotnet ef database update
   ↓
4. 数据库更新完成
```

**迁移文件示例**：

```csharp
public partial class AddEmailToUser : Migration
{
    protected override void Up(MigrationBuilder migrationBuilder)
    {
        migrationBuilder.AddColumn<string>(
            name: "Email",
            table: "Users",
            type: "nvarchar(256)",
            nullable: false,
            defaultValue: "");
    }

    protected override void Down(MigrationBuilder migrationBuilder)
    {
        migrationBuilder.DropColumn(
            name: "Email",
            table: "Users");
    }
}
```

**常用命令**：

| 命令                                        | 说明                       |
| ------------------------------------------- | -------------------------- |
| `dotnet ef migrations add <Name>`           | 创建新迁移                 |
| `dotnet ef database update`                 | 应用所有待处理迁移         |
| `dotnet ef database update <MigrationName>` | 回滚/升级到指定迁移        |
| `dotnet ef migrations remove`               | 删除最后一个迁移（未应用） |
| `dotnet ef migrations script`               | 生成 SQL 脚本              |

## 2. 如何将待处理的迁移应用到数据库？

**方法一：命令行（开发环境）**

```bash
# 应用所有待处理的迁移
dotnet ef database update

# 应用特定迁移
dotnet ef database update AddEmailToUser

# 回滚到指定迁移（包括删除数据）
dotnet ef database update 0  # 回滚所有
```

**方法二：代码自动迁移（启动时）**

```csharp
// Program.cs 或 Startup.cs
using (var scope = app.Services.CreateScope())
{
    var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    // 应用所有待处理的迁移
    dbContext.Database.Migrate();
}

// 或异步版本
await dbContext.Database.MigrateAsync();
```

**方法三：生成 SQL 脚本后手动执行（生产环境）**

```bash
# 生成迁移 SQL 脚本
dotnet ef migrations script --output migration.sql

# 从迁移 A 到迁移 B
dotnet ef migrations script MigrationA MigrationB --output changes.sql

# 幂等脚本（检查 __EFMigrationsHistory 表）
dotnet ef migrations script --idempotent --output idempotent.sql
```

```csharp
// 代码生成脚本
var script = dbContext.Database.GenerateCreateScript();
// 或生成迁移脚本
var migrationsScript = dbContext.Database.GenerateUpdateScript();
```

**方法四：确保数据库创建且迁移已应用**

```csharp
public static async Task EnsureDatabaseMigratedAsync(IServiceProvider services)
{
    using var scope = services.CreateScope();
    var context = scope.ServiceProvider.GetRequiredService<AppDbContext>();

    // 确保数据库存在并应用所有迁移
    await context.Database.MigrateAsync();

    // 或者只创建数据库（不应用迁移）
    // await context.Database.EnsureCreatedAsync();
}
```

## 3. Eager Loading（贪婪加载）、Explicit Loading（显式加载）和 Lazy Loading（延迟加载）的区别

| 加载方式             | 说明                                                  | 查询次数               | 使用时机                   | 性能特点                     |
| -------------------- | ----------------------------------------------------- | ---------------------- | -------------------------- | ---------------------------- |
| **Eager Loading**    | 使用 `Include()` 在**一次查询**中加载主实体和相关实体 | 1 次（JOIN）或额外查询 | 明确需要关联数据时         | 减少往返，但可能加载过多数据 |
| **Explicit Loading** | 先加载主实体，**需要时显式调用** `Load()` 加载关联    | N+1 次                 | 条件性加载，不确定是否需要 | 按需加载，但可能产生多次查询 |
| **Lazy Loading**     | 访问导航属性时**自动触发**数据库查询（需代理）        | N+1 次（意外）         | 简单场景，小型应用         | 容易引发 N+1 问题，慎用      |

**代码示例**：

```csharp
public class Blog
{
    public int Id { get; set; }
    public string Name { get; set; }
    public virtual ICollection<Post> Posts { get; set; }  // virtual 用于 Lazy Loading
}

// 1. Eager Loading（贪婪加载）
var blogs = context.Blogs
    .Include(b => b.Posts)           // 加载所有帖子
    .ThenInclude(p => p.Comments)    // 再加载帖子的评论
    .Include(b => b.Author)          // 同时加载作者
    .ToList();

// 拆分查询（避免 Cartesian explosion）
var blogs = context.Blogs
    .Include(b => b.Posts)
    .AsSplitQuery()  // 拆分为多个 SQL 查询
    .ToList();

// 2. Explicit Loading（显式加载）
var blog = context.Blogs.First();           // 只加载 Blog
if (needPosts)  // 条件满足时才加载
{
    context.Entry(blog).Collection(b => b.Posts).Load();
}

// 加载单个引用
context.Entry(blog).Reference(b => b.Author).Load();

// 3. Lazy Loading（延迟加载）
// 需要安装: dotnet add package Microsoft.EntityFrameworkCore.Proxies
// 配置: options.UseLazyLoadingProxies()
var blog = context.Blogs.First();           // 只加载 Blog
foreach (var post in blog.Posts)            // 访问时自动查询
{
    // 每次访问 blog.Posts 都会触发新的查询
}
```

**性能对比**：

```csharp
// ❌ 延迟加载陷阱（N+1 问题）
foreach (var blog in context.Blogs.ToList())      // 1 次查询
{
    foreach (var post in blog.Posts)              // 每次迭代 1 次查询（N 次）
    {
        Console.WriteLine(post.Title);
    }
}
// 100 个 Blog → 101 次查询

// ✅ 贪婪加载解决
var blogs = context.Blogs.Include(b => b.Posts).ToList();  // 1 次查询
```

## 4. 什么是导航属性（Navigation Properties）？为什么重要？

**导航属性** 是实体类中表示**关联关系**的属性，用于从一个实体访问相关实体。它们是 EF Core 中实现数据库关系的核心机制。

**类型**：

| 类型             | 说明                           | 示例                                           |
| ---------------- | ------------------------------ | ---------------------------------------------- |
| **引用导航属性** | 指向单个实体（多对一、一对一） | `public Author Author { get; set; }`           |
| **集合导航属性** | 指向实体集合（一对多、多对多） | `public ICollection<Post> Posts { get; set; }` |

**完整示例**：

```csharp
public class Author
{
    public int Id { get; set; }
    public string Name { get; set; }

    // 集合导航属性：一个作者有多篇文章
    public ICollection<Post> Posts { get; set; } = new List<Post>();
}

public class Post
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Content { get; set; }

    // 引用导航属性：文章属于一个作者
    public int AuthorId { get; set; }          // 外键属性
    public Author Author { get; set; }          // 引用导航属性

    // 另一个引用导航：文章有一个分类
    public int CategoryId { get; set; }
    public Category Category { get; set; }
}

public class Category
{
    public int Id { get; set; }
    public string Name { get; set; }

    // 集合导航属性：一个分类有多篇文章
    public ICollection<Post> Posts { get; set; }
}
```

**为什么重要**：

| 重要性         | 说明                                         |
| -------------- | -------------------------------------------- |
| **关系映射**   | 告诉 EF Core 实体之间如何关联（外键关系）    |
| **数据加载**   | 支持 `Include`、`Load`、延迟加载等           |
| **级联操作**   | 添加/删除时自动处理关联数据                  |
| **查询便利**   | 可以通过点号访问关联属性：`post.Author.Name` |
| **代码可读性** | 直观表达业务关系                             |

## 5. EF Core 映射中值类型（Value Types）和引用类型（Reference Types）的区别

| 特性           | 值类型（Owned Types）     | 引用类型（常规实体）              |
| -------------- | ------------------------- | --------------------------------- |
| **数据库映射** | 映射到**同一张表**的列    | 映射到**单独的表**或同一表（TPH） |
| **主键**       | 无独立主键，依赖所有者    | 有独立主键                        |
| **生命周期**   | 与所有者同生共死          | 独立生命周期                      |
| **独立查询**   | ❌ 不能独立查询           | ✅ 可独立查询                     |
| **共享性**     | 不可被多个实体共享        | 可被多个实体引用                  |
| **导航属性**   | 只能单向（所有者→值对象） | 可双向导航                        |

**值类型（Owned Types）示例**：

```csharp
// 值对象（不可变值语义）
[Owned]
public class Address
{
    public string Street { get; set; }
    public string City { get; set; }
    public string Country { get; set; }

    // 值类型的行为
    public string GetFullAddress() => $"{Street}, {City}, {Country}";
}

public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; }

    public Address HomeAddress { get; set; }      // 值类型属性
    public Address WorkAddress { get; set; }      // 可以有多个
}

// 数据库映射为单表 Customers 包含列:
// Id, Name, HomeAddress_Street, HomeAddress_City, HomeAddress_Country,
// WorkAddress_Street, WorkAddress_City, WorkAddress_Country
```

**引用类型（常规实体）示例**：

```csharp
public class Product
{
    public int Id { get; set; }           // 独立主键
    public string Name { get; set; }
    public int CategoryId { get; set; }
    public Category Category { get; set; } // 可被多个 Product 共享
}

public class Category
{
    public int Id { get; set; }
    public string Name { get; set; }
    public ICollection<Product> Products { get; set; }
}
```

**配置值类型（Owned Types）**：

```csharp
// Fluent API 配置
modelBuilder.Entity<Customer>(entity =>
{
    entity.OwnsOne(c => c.HomeAddress, address =>
    {
        address.Property(a => a.Street).HasColumnName("HomeStreet");
        address.Property(a => a.City).HasColumnName("HomeCity");
    });

    entity.OwnsOne(c => c.WorkAddress, address =>
    {
        address.Property(a => a.Street).HasColumnName("WorkStreet");
        address.Property(a => a.City).HasColumnName("WorkCity");
    });

    // 或者将值类型存储为 JSON（EF Core 7+）
    entity.OwnsOne(c => c.HomeAddress, address =>
    {
        address.ToJson();
    });
});
```

## 6. 如何在 EF Core 模型中配置关系（一对一、一对多、多对多）？

**三种配置方式**：

```csharp
// 方式一：约定配置（Conventions）
public class Blog
{
    public int Id { get; set; }
    public ICollection<Post> Posts { get; set; }  // 自动识别一对多
}

public class Post
{
    public int Id { get; set; }
    public int BlogId { get; set; }               // 外键属性
    public Blog Blog { get; set; }                 // 导航属性
}

// 方式二：数据注解（Attributes）
public class Blog
{
    public int Id { get; set; }

    [InverseProperty(nameof(Post.Blog))]          // 指定反向导航
    public ICollection<Post> Posts { get; set; }
}

public class Post
{
    public int Id { get; set; }

    [ForeignKey(nameof(Blog))]                    // 指定外键
    public int BlogForeignKey { get; set; }

    public Blog Blog { get; set; }
}

// 方式三：Fluent API（推荐，最灵活）
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 一对一、一对多、多对多都在这里配置
}
```

**各关系类型配置示例**：

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 1. 一对多（One-to-Many）
    modelBuilder.Entity<Blog>()
        .HasMany(b => b.Posts)           // Blog 有多个 Post
        .WithOne(p => p.Blog)            // Post 属于一个 Blog
        .HasForeignKey(p => p.BlogId)    // 外键
        .OnDelete(DeleteBehavior.Cascade);

    // 2. 一对一（One-to-One）
    modelBuilder.Entity<Person>()
        .HasOne(p => p.Passport)
        .WithOne(p => p.Person)
        .HasForeignKey<Passport>(p => p.PersonId);

    // 3. 多对多（Many-to-Many）- EF Core 5+
    modelBuilder.Entity<Student>()
        .HasMany(s => s.Courses)
        .WithMany(c => c.Students)
        .UsingEntity<StudentCourse>(
            j => j.HasOne(sc => sc.Course).WithMany().HasForeignKey(sc => sc.CourseId),
            j => j.HasOne(sc => sc.Student).WithMany().HasForeignKey(sc => sc.StudentId),
            j =>
            {
                j.Property(sc => sc.EnrollmentDate).HasDefaultValueSql("GETDATE()");
                j.ToTable("StudentCourses");
                j.HasKey(sc => new { sc.StudentId, sc.CourseId });
            });
}
```

## 7. 如何在 EF Core 中配置一对多关系？

**方法一：使用约定（无额外配置）**

```csharp
public class Category
{
    public int Id { get; set; }
    public string Name { get; set; }
    public ICollection<Product> Products { get; set; }  // 集合导航
}

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public int CategoryId { get; set; }                 // 外键（自动识别）
    public Category Category { get; set; }               // 引用导航
}
// EF Core 自动创建外键关系
```

**方法二：数据注解**

```csharp
public class Category
{
    public int Id { get; set; }
    public string Name { get; set; }

    [InverseProperty(nameof(Product.Category))]
    public ICollection<Product> Products { get; set; }
}

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }

    [ForeignKey(nameof(Category))]
    public int CategoryIdentifier { get; set; }

    public Category Category { get; set; }
}
```

**方法三：Fluent API（推荐，最灵活）**

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 标准一对多配置
    modelBuilder.Entity<Category>()
        .HasMany(c => c.Products)          // Category 有多个 Product
        .WithOne(p => p.Category)          // Product 属于一个 Category
        .HasForeignKey(p => p.CategoryId)  // 外键
        .OnDelete(DeleteBehavior.SetNull); // 删除 Category 时，Product.CategoryId 设为 NULL

    // 没有反向导航的一对多
    modelBuilder.Entity<Order>()
        .HasMany(o => o.OrderItems)
        .WithOne()
        .HasForeignKey(oi => oi.OrderId);

    // 自定义外键列名
    modelBuilder.Entity<Comment>()
        .HasOne(c => c.Post)
        .WithMany(p => p.Comments)
        .HasForeignKey(c => c.PostForeignKey);

    // 级联配置
    modelBuilder.Entity<Blog>()
        .HasMany(b => b.Posts)
        .WithOne(p => p.Blog)
        .OnDelete(DeleteBehavior.Restrict);  // 禁止级联删除
}
```

## 8. EF Core 如何处理级联删除（Cascade Delete）行为？

**级联删除行为类型**：

| 行为            | 说明                           | 使用场景                                            |
| --------------- | ------------------------------ | --------------------------------------------------- |
| `Cascade`       | 删除主实体时，自动删除依赖实体 | 强依赖关系（如订单-订单项）                         |
| `SetNull`       | 删除主实体时，将外键设为 NULL  | 可选关系（如用户-帖子，用户删除后帖子保留但无作者） |
| `Restrict`      | 阻止级联删除，需手动处理       | 重要数据保护（如不允许删除有订单的用户）            |
| `ClientCascade` | EF Core 7+，客户端级联         | 优化性能                                            |
| `ClientSetNull` | EF Core 7+，客户端设为 NULL    | 优化性能                                            |

**配置示例**：

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 全局配置（所有外键默认行为）
    foreach (var foreignKey in modelBuilder.Model.GetEntityTypes()
        .SelectMany(e => e.GetForeignKeys()))
    {
        foreignKey.DeleteBehavior = DeleteBehavior.Restrict;
    }

    // 单独配置
    modelBuilder.Entity<Blog>()
        .HasMany(b => b.Posts)
        .WithOne(p => p.Blog)
        .OnDelete(DeleteBehavior.Cascade);      // 删除 Blog 时删除所有 Post

    modelBuilder.Entity<User>()
        .HasMany(u => u.Posts)
        .WithOne(p => p.Author)
        .OnDelete(DeleteBehavior.SetNull);      // 删除用户时，Post.AuthorId = NULL

    modelBuilder.Entity<Order>()
        .HasMany(o => o.Items)
        .WithOne(i => i.Order)
        .OnDelete(DeleteBehavior.Restrict);     // 有订单项时不能删除订单
}
```

**实体类配置**：

```csharp
public class Blog
{
    public int Id { get; set; }
    public string Name { get; set; }
    public ICollection<Post> Posts { get; set; }
}

public class Post
{
    public int Id { get; set; }
    public string Title { get; set; }
    public int BlogId { get; set; }
    public Blog Blog { get; set; }
}

// 配置 Cascade 后，以下代码会级联删除所有 Post
context.Blogs.Remove(blog);
context.SaveChanges();
// 生成的 SQL: DELETE FROM Posts WHERE BlogId = 1; DELETE FROM Blogs WHERE Id = 1;
```

**级联删除限制（SQL Server）**：

```csharp
// 避免多路径级联（可能导致循环）
// ❌ 错误配置
modelBuilder.Entity<User>()
    .HasMany(u => u.CreatedOrders)
    .WithOne(o => o.Creator)
    .OnDelete(DeleteBehavior.Cascade);

modelBuilder.Entity<User>()
    .HasMany(u => u.ApprovedOrders)
    .WithOne(o => o.Approver)
    .OnDelete(DeleteBehavior.Cascade);
// SQL Server 报错：可能引起循环或多级联路径

// ✅ 解决方案：使用 Restrict 或 SetNull
modelBuilder.Entity<User>()
    .HasMany(u => u.ApprovedOrders)
    .WithOne(o => o.Approver)
    .OnDelete(DeleteBehavior.SetNull);
```

## 9. 跟踪实体（Tracked）与非跟踪实体（Untracked）的区别

| 特性                 | 跟踪实体（Tracked）   | 非跟踪实体（Untracked）  |
| -------------------- | --------------------- | ------------------------ |
| **变更检测**         | ✅ ChangeTracker 监控 | ❌ 无监控                |
| **SaveChanges 更新** | ✅ 自动生成 UPDATE    | ❌ 不会自动更新          |
| **性能**             | 较慢（需维护快照）    | 较快（无开销）           |
| **内存占用**         | 较高（存储快照）      | 较低                     |
| **适用场景**         | 需要修改并保存的实体  | 只读查询、报表、大量数据 |

**示例对比**：

```csharp
// 跟踪查询（默认）
var trackedBlog = context.Blogs.FirstOrDefault(b => b.Id == 1);
trackedBlog.Name = "New Name";
await context.SaveChangesAsync();  // ✅ 自动生成 UPDATE 语句

// 非跟踪查询
var untrackedBlog = context.Blogs
    .AsNoTracking()
    .FirstOrDefault(b => b.Id == 1);
untrackedBlog.Name = "New Name";
await context.SaveChangesAsync();  // ❌ 不会更新数据库

// 手动附加非跟踪实体（用于更新）
context.Blogs.Attach(untrackedBlog);
context.Entry(untrackedBlog).Property(b => b.Name).IsModified = true;
await context.SaveChangesAsync();  // ✅ 手动指定后可以更新
```

**查询跟踪状态**：

```csharp
var blog = context.Blogs.First();
var entry = context.Entry(blog);
Console.WriteLine(entry.State);  // EntityState.Unchanged

blog.Name = "Changed";
Console.WriteLine(entry.State);  // EntityState.Modified

// 获取所有跟踪实体
var trackedEntities = context.ChangeTracker.Entries()
    .Where(e => e.State != EntityState.Detached)
    .ToList();
```

## 10. AsNoTracking() 的作用及使用时机

**AsNoTracking()** 告诉 EF Core 不跟踪查询返回的实体，不会创建快照，不监控变更。

**主要作用**：

- 提高查询性能（减少 30-50% 开销）
- 减少内存占用
- 避免不必要的变更检测

**使用时机**：

```csharp
// ✅ 只读报表
var report = context.Orders
    .AsNoTracking()
    .Where(o => o.OrderDate >= startDate)
    .Select(o => new { o.Id, o.Total })
    .ToList();

// ✅ 只读列表页面
var products = context.Products
    .AsNoTracking()
    .Include(p => p.Category)
    .Take(100)
    .ToList();

// ✅ 大量数据读取（数据导出）
var allCustomers = context.Customers.AsNoTracking().ToArray();

// ✅ 不修改的数据
var configSettings = context.Settings.AsNoTracking().First();

// ❌ 需要修改后保存的数据
var order = context.Orders.Find(id);  // 不使用 AsNoTracking()
order.Status = "Shipped";
await context.SaveChangesAsync();

// ❌ 涉及事务更新
using var transaction = await context.Database.BeginTransactionAsync();
var product = context.Products.Find(id);  // 需要跟踪
product.Stock--;
await context.SaveChangesAsync();
```

**AsNoTrackingWithIdentityResolution（EF Core 5+）**：

```csharp
// 标准 AsNoTracking - 相同 ID 可能返回不同实例
var blogs1 = context.Blogs.AsNoTracking().ToList();
var blogs2 = context.Blogs.AsNoTracking().ToList();
// blogs1[0] != blogs2[0]（不同实例）

// AsNoTrackingWithIdentityResolution - 相同 ID 返回同一实例
var blogs3 = context.Blogs.AsNoTrackingWithIdentityResolution().ToList();
var blogs4 = context.Blogs.AsNoTrackingWithIdentityResolution().ToList();
// blogs3[0] == blogs4[0]（同一实例）
```

**性能对比**：

```csharp
// 测试代码
[Benchmark]
```

**全局配置 AsNoTracking**：

```csharp
// 方式一：DbContext 构造函数配置
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options)
    {
        ChangeTracker.QueryTrackingBehavior = QueryTrackingBehavior.NoTracking;
    }
}

// 方式二：按需覆盖（需要跟踪时单独指定）
var trackedBlog = context.Blogs
    .AsTracking()  // 覆盖全局配置
    .First();
```
