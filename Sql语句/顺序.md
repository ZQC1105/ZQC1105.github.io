## [SELECT（Transact-SQL）](https://learn.microsoft.com/zh-cn/sql/t-sql/queries/select-transact-sql?view=sql-server-ver17)

这是 SQL Server 中 **SELECT 语句的逻辑处理顺序**（也称为绑定顺序）。这个顺序很重要，因为它决定了每个子句的作用时机以及各子句中可用的对象。

## 逻辑处理顺序详解

### 1. **FROM** 和 **JOIN** 相关（步骤 1-3）

```
FROM → ON → JOIN
```

- **FROM**: 首先确定要查询的表或视图
- **ON**: 处理 JOIN 条件（对于 LEFT/RIGHT/INNER JOIN）
- **JOIN**: 执行表的连接操作
- **此时还未应用 WHERE 过滤**

### 2. **WHERE**（步骤 4）

- 对连接后的结果集进行行过滤
- **不能使用 SELECT 中定义的别名**（因为 SELECT 还没执行）

### 3. **GROUP BY**（步骤 5）

- 对数据进行分组
- 如果没有 GROUP BY，整个结果集被视为一个组

### 4. **CUBE/ROLLUP**（步骤 6）

- 生成分组统计的超级聚合行
- 这是可选的扩展功能

### 5. **HAVING**（步骤 7）

- 对分组后的结果进行过滤
- **只能使用 GROUP BY 中的列或聚合函数**

### 6. **SELECT**（步骤 8）

```
SELECT → DISTINCT
```

- 选择要返回的列
- 计算表达式
- **此时可以定义列别名**
- DISTINCT 去除重复行

### 7. **ORDER BY**（步骤 10）

- 对最终结果集进行排序
- **可以使用 SELECT 中定义的别名**
- 可以按列的位置编号排序（如 `ORDER BY 1, 2`）

### 8. **TOP**（步骤 11）

- SQL Server 特有的功能
- 限制返回的行数
- 在 ORDER BY 之后执行

## 实际执行顺序 vs 逻辑处理顺序

**重要区别**：查询优化器会根据效率重新安排**物理执行顺序**，但必须保证**逻辑结果**与这个处理顺序一致。

## 示例说明

```sql
-- 示例查询
SELECT
    YEAR(OrderDate) AS OrderYear,  -- 别名在 SELECT 步骤定义
    COUNT(*) AS TotalOrders
FROM Sales.Orders
WHERE Status = 'Shipped'          -- WHERE 不能使用 OrderYear 别名
GROUP BY YEAR(OrderDate)
HAVING COUNT(*) > 100            -- HAVING 可以使用聚合函数
ORDER BY OrderYear DESC          -- ORDER BY 可以使用别名
TOP 10;                         -- 最后取前10行
```

## 关键要点

1. **别名可用性**：
   - SELECT 中的别名只能在 ORDER BY、TOP 中使用
   - 不能在 WHERE、GROUP BY、HAVING 中使用

2. **错误示例**：

   ```sql
   -- 错误：WHERE 不能使用 SELECT 的别名
   SELECT Column1 AS C1
   FROM Table1
   WHERE C1 = 'Value'  -- 错误！C1 还不存在
   ```

3. **正确做法**：
   ```sql
   -- 正确：在 WHERE 中使用原始列名
   SELECT Column1 AS C1
   FROM Table1
   WHERE Column1 = 'Value'
   ORDER BY C1  -- 正确：ORDER BY 可以使用别名
   ```

理解这个逻辑顺序有助于：

- 避免语法错误
- 编写更高效的查询
- 理解查询的执行逻辑
- 调试复杂的 SQL 语句
