## ASP.NET Core 中间件顺序的核心原则

**“按请求处理顺序注册，按相反顺序执行响应”**

更形象地说：**先注册的中间件先处理请求，后注册的中间件后处理请求，响应时反过来**。

## 标准 Production 顺序（官方推荐）

```csharp
var app = builder.Build();

// 1. 异常处理（最早，能捕获后续所有中间件的异常）
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();  // 开发环境详细错误页
}
else
{
    app.UseExceptionHandler("/error"); // 生产环境错误处理
    app.UseHsts();                     // HTTP 严格传输安全
}

// 2. HTTPS 重定向
app.UseHttpsRedirection();

// 3. 静态文件（提前，避免不必要的处理）
app.UseStaticFiles();

// 4. 路由（关键决策点）
app.UseRouting();

// 5. 认证（必须在授权之前）
app.UseAuthentication();

// 6. 授权
app.UseAuthorization();

// 7. 端点映射（最后）
app.MapControllers();
app.MapRazorPages();
// 或其他端点
```

## 为什么是这个顺序？

### 关键依赖关系
```csharp
UseRouting()      // 决定"去哪个 Action"
    ↓
UseAuthentication() // 需要知道路由结果来确定认证策略
    ↓
UseAuthorization()  // 依赖认证结果做授权决策
    ↓
UseEndpoints()      // 最终执行
```

### 错误示例对比

**❌ 错误顺序（认证在路由前）**
```csharp
app.UseAuthentication();  // 还不知道要访问哪个端点
app.UseRouting();         // 路由信息此时才可用
app.UseAuthorization();
// 问题：认证中间件可能无法正确获取端点元数据
```

**✅ 正确顺序**
```csharp
app.UseRouting();         // 先确定端点
app.UseAuthentication();  // 基于端点做认证
app.UseAuthorization();   // 基于认证结果做授权
```

## 常用中间件完整示例

```csharp
var app = builder.Build();

// 开发环境
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
    app.UseSwagger();                    // Swagger 文档
    app.UseSwaggerUI();
}
else
{
    app.UseExceptionHandler("/error");
    app.UseHsts();
}

// 基础中间件
app.UseHttpsRedirection();
app.UseStaticFiles();                    // wwwroot 静态文件

// 自定义中间件（可以插在这里）
app.UseMiddleware<RequestLoggingMiddleware>();
app.UseMiddleware<RequestCultureMiddleware>();

// 核心三件套（顺序固定）
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();

// CORS（位置灵活，但通常在认证授权前后有讲究）
app.UseCors("AllowSpecificOrigin");

// 端点
app.MapControllers();
app.MapRazorPages();
app.MapHealthChecks("/health");

app.Run();
```

## CORS 的位置选择

```csharp
// 方案1：在路由之前（推荐）
app.UseCors();           // 全局 CORS
app.UseRouting();
// 优势：最早处理跨域预检请求

// 方案2：在授权之前
app.UseRouting();
app.UseCors();           // 确保授权时已处理 CORS
app.UseAuthentication();
app.UseAuthorization();
```

## 自定义中间件的位置

```csharp
// 需要记录所有请求 → 放在最前面
app.UseMiddleware<LoggingMiddleware>();

// 需要修改响应 → 放在 UseEndpoints 之前
app.UseMiddleware<ResponseModificationMiddleware>();

// 需要捕获异常 → 放在异常处理之后
app.UseExceptionHandler("/error");
app.UseMiddleware<CustomErrorHandlingMiddleware>();
```

## 快速记忆口诀

> **异静路，认授端**  
> 异常 → 静态文件 → 路由 → 认证 → 授权 → 端点

或者更完整版：
> **异(异常)静(静态)路(路由)，认(认证)授(授权)端(端点)**

## 验证方法

你可以通过中间件顺序测试：
```csharp
app.Use(async (context, next) =>
{
    Debug.WriteLine("1. 请求进入");
    await next();
    Debug.WriteLine("6. 响应离开");
});

app.UseRouting();

app.Use(async (context, next) =>
{
    Debug.WriteLine("2. 路由后");
    await next();
    Debug.WriteLine("5. 响应返回");
});

app.UseEndpoints(_ => { });
// 在端点中输出 "3. 执行 Action" 和 "4. Action 返回"
```

这个顺序是 ASP.NET Core 生产环境的标准实践，掌握了它就能避免 90% 的中间件顺序问题。
