## 31. 如何在 EF Core 中实现乐观并发令牌（Optimistic Concurrency Tokens）？

乐观并发控制使用**并发令牌**检测并发冲突，不锁数据，在保存时检查数据是否被修改。

**方法一：使用 RowVersion（SQL Server 推荐）**

```csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }

    [Timestamp]  // 自动生成并发令牌
    public byte[] RowVersion { get; set; }
}

// Fluent API 配置
modelBuilder.Entity<Product>()
    .Property(p => p.RowVersion)
    .IsRowVersion();
```

**方法二：使用 IsConcurrencyToken**

```csharp
public class Product
{
    public int Id { get; set; }

    [ConcurrencyCheck]  // 检查此字段的并发
    public string Name { get; set; }

    [ConcurrencyCheck]
    public int Stock { get; set; }
}

// Fluent API
modelBuilder.Entity<Product>()
    .Property(p => p.Stock)
    .IsConcurrencyToken();
```

**方法三：自定义并发令牌（多个字段组合）**

```csharp
modelBuilder.Entity<Blog>()
    .Property(b => b.LastUpdated)
    .IsConcurrencyToken()
    .HasDefaultValueSql("GETDATE()");
```

**处理并发冲突**：

```csharp
public async Task<bool> UpdateProductAsync(int id, string newName, decimal newPrice)
{
    using var context = new AppDbContext();
    var maxRetries = 3;
    var retryCount = 0;

    while (retryCount < maxRetries)
    {
        try
        {
            var product = await context.Products.FindAsync(id);
            product.Name = newName;
            product.Price = newPrice;

            await context.SaveChangesAsync();
            return true;
        }
        catch (DbUpdateConcurrencyException ex)
        {
            retryCount++;

            foreach (var entry in ex.Entries)
            {
                var databaseValues = await entry.GetDatabaseValuesAsync();

                if (databaseValues == null)
                {
                    // 记录已被删除
                    return false;
                }

                // 获取冲突的值
                var currentValues = entry.CurrentValues;
                var originalValues = entry.OriginalValues;

                // 策略1：数据库获胜（放弃更改）
                // entry.CurrentValues.SetValues(databaseValues);

                // 策略2：客户端获胜（覆盖数据库）
                entry.OriginalValues.SetValues(databaseValues);

                // 策略3：合并（显示冲突让用户决定）
                var conflicts = new Dictionary<string, (object Client, object Database)>();
                foreach (var property in currentValues.Properties)
                {
                    var clientValue = currentValues[property];
                    var dbValue = databaseValues[property];
                    if (!Equals(clientValue, dbValue))
                    {
                        conflicts[property.Name] = (clientValue, dbValue);
                    }
                }

                if (conflicts.Any())
                {
                    // 返回冲突信息，让客户端处理
                    throw new ConcurrencyConflictException(conflicts);
                }
            }
        }
    }

    return false;
}
```

**使用 ExecuteUpdate 的并发处理**：

```csharp
// 使用原始 SQL 或 ExecuteUpdate 处理并发
var result = await context.Products
    .Where(p => p.Id == id && p.Stock >= quantity)
    .ExecuteUpdateAsync(setters => setters
        .SetProperty(p => p.Stock, p => p.Stock - quantity)
        .SetProperty(p => p.RowVersion, p => SqlDbExtensions.RowVersion())); // 自动更新
```

## 32. EF Core 中的连接池行为

EF Core **依赖底层 ADO.NET 连接池**，默认行为是**每个 DbContext 实例在需要时从池中获取连接，释放时归还**。

**默认连接池行为**：

```csharp
// 连接字符串启用池（默认开启）
"Server=localhost;Database=MyDb;Pooling=true;Min Pool Size=5;Max Pool Size=100;"

// 每个 DbContext 实例
using (var context = new AppDbContext())  // 从池获取连接
{
    var products = context.Products.ToList();  // 使用连接
}  // 释放时归还连接到池
```

**重要行为**：

| 行为                     | 说明                            |
| ------------------------ | ------------------------------- |
| **默认最大连接数**       | 100（可配置）                   |
| **连接延迟打开**         | 首次查询时才打开连接            |
| **连接及时关闭**         | SaveChanges 后关闭（不等待 GC） |
| **DbContext 不管理连接** | 底层 ADO.NET 连接池管理         |
| **连接泄漏风险**         | 长时间运行的查询未 Dispose      |

**最佳实践**：

```csharp
// ✅ 正确：短生命周期
public async Task<List<Product>> GetProductsAsync()
{
    using var context = new AppDbContext();  // 及时释放
    return await context.Products.AsNoTracking().ToListAsync();
}

// ❌ 错误：长生命周期（单例 DbContext）
builder.Services.AddSingleton<AppDbContext>();  // 不要这样做！

// ✅ 正确：Scoped 生命周期（Web 应用）
builder.Services.AddScoped<AppDbContext>();  // 每个请求一个实例

// 手动控制连接
using var context = new AppDbContext();
await context.Database.OpenConnectionAsync();  // 手动打开
// ... 操作
await context.Database.CloseConnectionAsync();  // 手动关闭
```

**连接池监控**：

```csharp
// 获取连接池统计信息
using var context = new AppDbContext();
var connection = context.Database.GetDbConnection();

if (connection is SqlConnection sqlConn)
{
    var stats = sqlConn.StatisticsEnabled;
    sqlConn.StatisticsEnabled = true;
    // 执行查询后
    var statistics = sqlConn.RetrieveStatistics();
    Console.WriteLine($"连接数: {statistics["Connections"]}");
}
```

## 33. 如何使用拦截器（Interceptors）自定义 EF Core 行为？

**拦截器** 允许在 EF Core 操作（查询、保存、连接）前后注入自定义逻辑。

**常用拦截器类型**：

| 拦截器                       | 用途             |
| ---------------------------- | ---------------- |
| `SaveChangesInterceptor`     | 保存操作前后     |
| `DbCommandInterceptor`       | SQL 命令执行前后 |
| `ConnectionInterceptor`      | 数据库连接操作   |
| `MaterializationInterceptor` | 实体实例化时     |
| `DiagnosticInterceptor`      | 诊断和日志       |

**示例 1：查询性能监控**

```csharp
public class PerformanceInterceptor : DbCommandInterceptor
{
    private readonly ILogger<PerformanceInterceptor> _logger;

    public PerformanceInterceptor(ILogger<PerformanceInterceptor> logger)
    {
        _logger = logger;
    }

    private readonly Stopwatch _stopwatch = new();

    public override InterceptionResult<DbDataReader> ReaderExecuting(
        DbCommand command, CommandEventData eventData, InterceptionResult<DbDataReader> result)
    {
        _stopwatch.Restart();
        return base.ReaderExecuting(command, eventData, result);
    }

    public override DbDataReader ReaderExecuted(
        DbCommand command, CommandExecutedEventData eventData, DbDataReader result)
    {
        _stopwatch.Stop();
        if (_stopwatch.ElapsedMilliseconds > 1000)
        {
            _logger.LogWarning("慢查询 ({Elapsed}ms): {Command}",
                _stopwatch.ElapsedMilliseconds, command.CommandText);
        }
        return base.ReaderExecuted(command, eventData, result);
    }
}
```

**示例 2：软删除拦截器**

```csharp
public class SoftDeleteInterceptor : SaveChangesInterceptor
{
    private readonly IHttpContextAccessor _httpContextAccessor;

    public SoftDeleteInterceptor(IHttpContextAccessor httpContextAccessor)
    {
        _httpContextAccessor = httpContextAccessor;
    }

    public override InterceptionResult<int> SavingChanges(
        DbContextEventData eventData, InterceptionResult<int> result)
    {
        ApplySoftDelete(eventData.Context);
        return base.SavingChanges(eventData, result);
    }

    private void ApplySoftDelete(DbContext? context)
    {
        if (context == null) return;

        var entries = context.ChangeTracker.Entries()
            .Where(e => e.State == EntityState.Deleted && e.Entity is ISoftDelete);

        foreach (var entry in entries)
        {
            entry.State = EntityState.Modified;
            ((ISoftDelete)entry.Entity).IsDeleted = true;
            ((ISoftDelete)entry.Entity).DeletedAt = DateTime.UtcNow;
        }
    }
}
```

**示例 3：审计日志拦截器**

```csharp
public class AuditInterceptor : SaveChangesInterceptor
{
    public override async ValueTask<int> SavingChangesAsync(
        DbContextEventData eventData, InterceptionResult<int> result, CancellationToken ct = default)
    {
        if (eventData.Context != null)
        {
            var auditEntries = eventData.Context.ChangeTracker.Entries()
                .Where(e => e.State is EntityState.Added or EntityState.Modified or EntityState.Deleted)
                .Select(e => new AuditEntry
                {
                    EntityType = e.Entity.GetType().Name,
                    State = e.State.ToString(),
                    Timestamp = DateTime.UtcNow,
                    Changes = e.Properties
                        .Where(p => p.IsModified || e.State == EntityState.Added)
                        .ToDictionary(p => p.Metadata.Name, p => p.CurrentValue)
                })
                .ToList();

            // 保存审计日志到另一个数据库
            await SaveAuditLogsAsync(auditEntries);
        }

        return await base.SavingChangesAsync(eventData, result, ct);
    }
}
```

**注册拦截器**：

```csharp
// Program.cs
builder.Services.AddSingleton<PerformanceInterceptor>();
builder.Services.AddScoped<SoftDeleteInterceptor>();
builder.Services.AddScoped<AuditInterceptor>();

builder.Services.AddDbContext<AppDbContext>((sp, options) =>
    options.UseSqlServer(connectionString)
           .AddInterceptors(
               sp.GetRequiredService<PerformanceInterceptor>(),
               sp.GetRequiredService<SoftDeleteInterceptor>()));
```

## 34. 跟踪图（Tracking Graphs）与附加分离实体（Attaching Detached Entities）的区别

| 概念             | 说明                                             | 适用场景               |
| ---------------- | ------------------------------------------------ | ---------------------- |
| **跟踪图**       | EF Core 自动跟踪的实体关系图（包括所有导航属性） | 从数据库查询的实体     |
| **附加分离实体** | 将之前分离的实体重新附加到 ChangeTracker         | 更新从客户端传来的实体 |

**跟踪图示例**：

```csharp
// 查询时 EF Core 构建跟踪图
var blog = context.Blogs
    .Include(b => b.Posts)
    .First();

// blog 和 blog.Posts 都被跟踪
// blog 和 posts 之间的关系也被跟踪
blog.Name = "New Name";
blog.Posts[0].Title = "New Title";

await context.SaveChangesAsync();  // 同时更新 Blog 和 Post
```

**附加分离实体**：

```csharp
// 场景：Web API 接收更新请求
[HttpPut]
public async Task UpdateBlog(BlogDto blogDto)
{
    // blogDto 是分离的实体（来自客户端）
    var blog = new Blog { Id = blogDto.Id, Name = blogDto.Name };

    // 方法1：Attach + 手动标记修改
    context.Blogs.Attach(blog);
    context.Entry(blog).Property(b => b.Name).IsModified = true;

    // 方法2：Update（标记所有属性为修改）
    context.Blogs.Update(blog);  // 会更新所有字段

    await context.SaveChangesAsync();
}
```

**处理复杂分离图**：

```csharp
// 分离的实体图（Blog + Posts）
public async Task UpdateBlogWithPosts(Blog blog)
{
    // blog 来自客户端，Posts 可能被添加/删除/修改

    // 方法1：TrackGraph 手动处理每个实体
    context.ChangeTracker.TrackGraph(blog, node =>
    {
        var entry = node.Entry;
        var entity = node.Entry.Entity;

        if (entity.Id == 0)
        {
            entry.State = EntityState.Added;  // 新实体
        }
        else if (entry.IsKeySet)
        {
            entry.State = EntityState.Modified;  // 现有实体
        }
    });

    await context.SaveChangesAsync();
}

// 方法2：使用 Update 并处理子实体
public async Task UpdateBlogWithPosts(Blog blog)
{
    // 先附加主实体
    context.Blogs.Update(blog);

    // 处理 Posts
    foreach (var post in blog.Posts)
    {
        if (post.Id == 0)
            context.Posts.Add(post);  // 新增
        else
            context.Posts.Update(post);  // 更新
    }

    await context.SaveChangesAsync();
}
```

**跟踪图状态**：

```csharp
var blog = context.Blogs.Include(b => b.Posts).First();

Console.WriteLine(context.Entry(blog).State);  // Unchanged
Console.WriteLine(context.Entry(blog.Posts[0]).State);  // Unchanged

// 修改关系
blog.Posts.Remove(blog.Posts[0]);
Console.WriteLine(context.Entry(blog.Posts[0]).State);  // Deleted
```

## 35. 是否在 EF Core 中使用 Repository 模式？

**观点：通常不需要，EF Core 的 DbContext 已经实现了 UnitOfWork + Repository**

**Repository 模式的优缺点**：

| 方面         | 使用 Repository           | 不使用 Repository（直接使用 DbContext） |
| ------------ | ------------------------- | --------------------------------------- |
| **抽象层**   | 多一层抽象                | 直接暴露 EF Core                        |
| **测试**     | 可轻松 Mock               | 需使用 InMemory 或 SQLite               |
| **代码量**   | 更多样板代码              | 更少                                    |
| **功能限制** | 可能隐藏 EF Core 高级特性 | 完全访问 EF Core API                    |
| **切换 ORM** | 更容易（很少发生）        | 困难                                    |

**不使用 Repository 的示例（推荐小型项目）**：

```csharp
public class ProductService
{
    private readonly AppDbContext _context;

    public ProductService(AppDbContext context)
    {
        _context = context;
    }

    public async Task<List<Product>> GetActiveProductsAsync()
    {
        return await _context.Products
            .Where(p => p.IsActive)
            .Include(p => p.Category)
            .AsNoTracking()
            .ToListAsync();
    }
}
```

**需要 Repository 的场景**：

```csharp

public class ProductRepository : IProductRepository

    {

    }

// 3. 需要统一规范查询（如软删除、多租户）
```

## 36. UnitOfWork 模式及其与 EF Core 的关系

**UnitOfWork** 将多个数据库操作组合为一个**原子事务**，要么全部成功，要么全部失败。

**EF Core 的 DbContext 本身就是 UnitOfWork**：

```csharp
// DbContext 自动实现 UnitOfWork
public class OrderService
{
    private readonly AppDbContext _context;  // 这就是 UnitOfWork

    public async Task CreateOrderAsync(Order order)
    {
        _context.Orders.Add(order);

        // 更新库存
        foreach (var item in order.Items)
        {
            var product = await _context.Products.FindAsync(item.ProductId);
            product.Stock -= item.Quantity;
        }

        // 记录日志
        _context.Logs.Add(new Log($"Order {order.Id} created"));

        // 所有操作作为一个事务提交
        await _context.SaveChangesAsync();  // UnitOfWork 提交
    }
}
```

**手动实现 UnitOfWork（多 DbContext 场景）**：

```csharp
public interface IUnitOfWork : IDisposable
{
    IProductRepository Products { get; }
    IOrderRepository Orders { get; }
    IUserRepository Users { get; }

    Task<int> SaveChangesAsync();
    Task BeginTransactionAsync();
    Task CommitTransactionAsync();
    Task RollbackTransactionAsync();
}

public class UnitOfWork : IUnitOfWork
{
    private readonly AppDbContext _context;
    private IDbContextTransaction? _transaction;

    public IProductRepository Products { get; }
    public IOrderRepository Orders { get; }
    public IUserRepository Users { get; }

    public UnitOfWork(AppDbContext context)
    {
        _context = context;
        Products = new ProductRepository(_context);
        Orders = new OrderRepository(_context);
        Users = new UserRepository(_context);
    }

    public async Task<int> SaveChangesAsync() => await _context.SaveChangesAsync();

    public async Task BeginTransactionAsync()
    {
        _transaction = await _context.Database.BeginTransactionAsync();
    }

    public async Task CommitTransactionAsync()
    {
        try
        {
            await SaveChangesAsync();
            await _transaction?.CommitAsync();
        }
        catch
        {
            await RollbackTransactionAsync();
            throw;
        }
        finally
        {
            _transaction?.Dispose();
            _transaction = null;
        }
    }

    public async Task RollbackTransactionAsync()
    {
        await _transaction?.RollbackAsync();
        _transaction?.Dispose();
        _transaction = null;
    }

    public void Dispose() => _transaction?.Dispose();
}
```

## 37. 如何在 EF Core 中启动事务？

```csharp
_context.Products.Add(product1);
```

## 38. 如何处理跨多个 DbContext 的事务边界？

**方法一：使用 TransactionScope（分布式事务）**

```csharp
using var scope = new TransactionScope(TransactionScopeAsyncFlowOption.Enabled);

try
{
    // DbContext 1
    using var context1 = new OrderDbContext();
    context1.Orders.Add(order);
    await context1.SaveChangesAsync();

    // DbContext 2
    using var context2 = new InventoryDbContext();
    context2.Products.Find(productId).Stock -= quantity;
    await context2.SaveChangesAsync();

    scope.Complete();  // 提交分布式事务
}
catch
{
    // 自动回滚
}
```

**方法二：手动管理连接（同一数据库）**

```csharp
// 使用相同的连接字符串，共享连接
using var connection = new SqlConnection(connectionString);
await connection.OpenAsync();

using var transaction = connection.BeginTransaction();

try
{
    using var context1 = new OrderDbContext(connection);
    await context1.Database.UseTransactionAsync(transaction);

    using var context2 = new InventoryDbContext(connection);
    await context2.Database.UseTransactionAsync(transaction);

    // 操作...

    transaction.Commit();
}
catch
{
    transaction.Rollback();
}
```

**方法三：自定义 DbContext 工厂共享事务**

```csharp
public class SharedTransactionManager
{
    private IDbContextTransaction? _transaction;
    private readonly List<DbContext> _contexts = new();

    public async Task<T> ExecuteInTransactionAsync<T>(Func<Task<T>> action)
    {
        try
        {
            var result = await action();

            foreach (var context in _contexts)
            {
                await context.SaveChangesAsync();
            }

            _transaction?.Commit();
            return result;
        }
        catch
        {
            _transaction?.Rollback();
            throw;
        }
        finally
        {
            _transaction?.Dispose();
        }
    }

    public async Task RegisterContextAsync(DbContext context)
    {
        if (_transaction == null)
        {
            await context.Database.OpenConnectionAsync();
            _transaction = await context.Database.BeginTransactionAsync();
        }
        else
        {
            await context.Database.UseTransactionAsync(_transaction.GetDbTransaction());
        }

        _contexts.Add(context);
    }
}
```

## 39. 如何使用多个 DbContext 实现读写分离（CQRS）？

**CQRS 读写分离**：读使用无跟踪查询（可能用读库），写使用有跟踪（用主库）。

**方法一：两个 DbContext 不同连接字符串**

```csharp
// 配置
builder.Services.AddDbContext<WriteDbContext>(options =>
    options.UseSqlServer(writeConnectionString));

builder.Services.AddDbContext<ReadDbContext>(options =>
    options.UseSqlServer(readConnectionString)  // 读库连接
        .UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking));

// 使用
public class ProductService
{
    private readonly WriteDbContext _writeContext;
    private readonly ReadDbContext _readContext;

    // 写操作
    public async Task CreateProductAsync(Product product)
    {
        _writeContext.Products.Add(product);
        await _writeContext.SaveChangesAsync();
    }

    // 读操作
    public async Task<List<ProductDto>> GetProductsAsync()
    {
        return await _readContext.Products
            .Select(p => new ProductDto { ... })
            .ToListAsync();
    }
}
```

**方法二：单一 DbContext + 拦截器切换连接**

```csharp
public class ReadWriteInterceptor : DbConnectionInterceptor
{
    private readonly string _writeConnectionString;
    private readonly string _readConnectionString;
    private readonly IHttpContextAccessor _httpContextAccessor;

    public ReadWriteInterceptor(
        string writeConnectionString,
        string readConnectionString,
        IHttpContextAccessor httpContextAccessor)
    {
        _writeConnectionString = writeConnectionString;
        _readConnectionString = readConnectionString;
        _httpContextAccessor = httpContextAccessor;
    }

    public override InterceptionResult ConnectionOpening(
        DbConnection connection, ConnectionEventData eventData, InterceptionResult result)
    {
        var isReadOnly = _httpContextAccessor.HttpContext?.Items["IsReadOnly"] as bool? ?? false;
        connection.ConnectionString = isReadOnly ? _readConnectionString : _writeConnectionString;
        return result;
    }
}

// 使用

{
    public async Task Handle()
    {
        _httpContextAccessor.HttpContext.Items["IsReadOnly"] = true;
        // 后续查询使用读库
    }
}
```

## 40. 如何在生产环境应用迁移？

**方法一：生成 SQL 脚本，DBA 执行（最安全）**

```bash
# 生成幂等脚本（检查 __EFMigrationsHistory）
dotnet ef migrations script --idempotent --output migrate.sql

# 生成从特定迁移到最新的脚本
dotnet ef migrations script PreviousMigrationName --output upgrade.sql

# 生成完整数据库脚本（首次部署）
dotnet ef migrations script 0 --output create.sql
```

**方法二：启动时自动迁移**

```csharp
// Program.cs
var app = builder.Build();

using (var scope = app.Services.CreateScope())
{
    var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    // 应用待处理迁移
    await dbContext.Database.MigrateAsync();
}

app.Run();
```

**方法三：使用部署工具（Azure DevOps/GitHub Actions）**

```yaml
# GitHub Actions 示例
- name: Apply EF Migrations
  run: |
    dotnet tool install --global dotnet-ef
    dotnet ef database update --connection "${{ secrets.DB_CONNECTION }}"
```

**方法四：使用迁移包（bundle）**

```bash
# 创建自包含的迁移包
dotnet ef migrations bundle --self-contained -r linux-x64 --output migrate

# 在生产环境运行
./migrate --connection "Server=prod;Database=MyDb;..."
```
