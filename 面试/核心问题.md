## 一、ASP.NET Core 依赖注入

### 问题1：请解释一下AddTransient、AddScoped、AddSingleton的区别？

**解答：**

| 生命周期      | 实例创建时机                 | 适用场景                                    |
| ------------- | ---------------------------- | ------------------------------------------- |
| **Transient** | 每次请求都创建新实例         | 轻量级、无状态的服务                        |
| **Scoped**    | 每个HTTP请求内共享同一个实例 | 每个请求内需要保持状态的服务（如DbContext） |
| **Singleton** | 应用启动时创建，全局唯一     | 全局配置、日志、缓存等                      |

**代码示例：**
```csharp
// Transient：每次获取都是新实例
services.AddTransient<ITransientService, TransientService>();

// Scoped：同一HTTP请求内是同一个实例
services.AddScoped<IScopedService, ScopedService>();

// Singleton：全局只有一个实例
services.AddSingleton<ISingletonService, SingletonService>();
```

**面试加分点：** 提到DbContext默认是Scoped，避免在Singleton中注入Scoped服务（会变成Captive Dependency）。

---

### 问题2：如何在一个Singleton服务中使用Scoped服务？

**解答：**

不能直接注入，需要使用`IServiceScopeFactory`创建作用域。

```csharp
public class MySingletonService
{
    private readonly IServiceScopeFactory _scopeFactory;
    
    public MySingletonService(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }
    
    public async Task DoWorkAsync()
    {
        using var scope = _scopeFactory.CreateScope();
        var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        // 使用dbContext
    }
}
```

**面试加分点：** 提到需要手动`Dispose`作用域，避免内存泄漏。

---

### 问题3：什么是Captive Dependency？如何避免？

**解答：**

Captive Dependency（受困依赖）是指**生命周期较长的服务持有了生命周期较短的服务**。

**错误示例：**
```csharp
// Singleton持有了Scoped的DbContext
services.AddSingleton<ISingletonService, SingletonService>(); // ❌
services.AddScoped<AppDbContext>();
```

**问题：** DbContext不是线程安全的，Singleton持有时会导致多线程问题。

**解决方案：**
- 使用`IServiceScopeFactory`（见问题2）
- 或者调整服务的生命周期，让外层生命周期不短于内层

## 二、EF Core 性能优化

### 问题1：什么是N+1查询问题？如何解决？

**解答：**

N+1问题是指：查询主实体后，循环访问每个实体的导航属性，导致额外执行N次查询。

**问题代码：**
```csharp
// 1次查询获取所有订单
var orders = context.Orders.ToList();

// N次查询：每个订单都单独查一次Customer
foreach (var order in orders)
{
    var customerName = order.Customer.Name; // 触发额外查询
}
```

**解决方案：**

| 方法              | 代码                                                         | 适用场景         |
| ----------------- | ------------------------------------------------------------ | ---------------- |
| **Include**       | `.Include(o => o.Customer)`                                  | 预先加载关联数据 |
| **ThenInclude**   | `.Include(o => o.Customer).ThenInclude(c => c.Address)`      | 多级关联         |
| **Select投影**    | `.Select(o => new { o.Id, CustomerName = o.Customer.Name })` | 只需要部分字段   |
| **Split Queries** | `.AsSplitQuery()`                                            | 避免笛卡尔积爆炸 |

```csharp
// 使用Include解决
var orders = context.Orders
    .Include(o => o.Customer)
    .ToList();
```

### 问题2：如何监控和发现EF Core的性能问题？

**解答：**

**1. 使用LogTo输出SQL**
```csharp
optionsBuilder.LogTo(Console.WriteLine, LogLevel.Information)
    .EnableSensitiveDataLogging()  // 显示参数值
    .EnableDetailedErrors();        // 详细错误
```

**2. 使用ToQueryString()查看SQL**
```csharp
var query = context.Orders.Where(o => o.Price > 100);
var sql = query.ToQueryString();  // 查看生成的SQL
```

**3. 使用第三方工具**
- **MiniProfiler**：查看每个请求的SQL执行时间
- **EF Core Power Tools**：可视化分析查询

**4. 关注这些指标**
- 执行时间 > 200ms 的查询
- 循环内执行的查询（N+1）
- 没有WHERE条件的全表扫描
- 客户端评估（Client Evaluation）

### 问题3：什么是客户端评估？为什么应该避免？

**解答：**

客户端评估是指EF Core无法将LINQ查询转换为SQL，而是在客户端（内存中）执行过滤。

**客户端评估示例：**
```csharp
// ❌ 使用C#方法，无法翻译成SQL
var orders = context.Orders
    .Where(o => Regex.IsMatch(o.OrderNo, @"^\d{6}$"))
    .ToList();  // 所有数据加载到内存，再过滤
```

**服务端评估（正确）：**
```csharp
// ✅ 使用SQL支持的函数
var orders = context.Orders
    .Where(o => EF.Functions.Like(o.OrderNo, "______"))  // 6个下划线
    .ToList();
```

**如何发现客户端评估：**
- 查看日志：会输出`The LINQ expression could not be translated`
- 升级到EF Core 6/7/8：会抛出异常而不是静默执行

**常见触发客户端评估的操作：**
- 使用自定义C#方法
- `ToString()`、`DateTime.Now`的某些用法
- `IEnumerable`而非`IQueryable`

## 三、SQL 复杂查询

### 问题1：请解释INNER JOIN、LEFT JOIN、RIGHT JOIN的区别，并举例说明LEFT JOIN的应用场景。

**解答：**

| JOIN类型       | 结果                               | 说明               |
| -------------- | ---------------------------------- | ------------------ |
| **INNER JOIN** | 只返回两表匹配的行                 | 双方都有才返回     |
| **LEFT JOIN**  | 返回左表所有行，右表无匹配则为NULL | 左表为主           |
| **RIGHT JOIN** | 返回右表所有行，左表无匹配则为NULL | 右表为主（较少用） |

**LEFT JOIN应用场景：查询所有客户及其订单（即使没有订单的客户也要显示）：**
```sql
SELECT c.Name, o.OrderNo, o.Amount
FROM Customers c
LEFT JOIN Orders o ON c.Id = o.CustomerId
-- 没有订单的客户也会显示，订单字段为NULL
```

**面试加分点：** 说明`LEFT JOIN`可以配合`WHERE右表字段 IS NULL`来查找“不存在”的记录，例如：查询从未下过订单的客户。

### 问题2：请写出一个使用窗口函数（如ROW_NUMBER、RANK）的查询示例。

**解答：**

**场景：** 查询每个分类下销售额最高的前3个产品。

```sql
WITH RankedProducts AS (
    SELECT 
        ProductName,
        CategoryId,
        SalesAmount,
        ROW_NUMBER() OVER (PARTITION BY CategoryId ORDER BY SalesAmount DESC) AS rn
    FROM Products
)
SELECT ProductName, CategoryId, SalesAmount
FROM RankedProducts
WHERE rn <= 3;
```

**窗口函数对比：**

| 函数           | 说明       | 处理并列情况   |
| -------------- | ---------- | -------------- |
| `ROW_NUMBER()` | 1,2,3,4... | 并列时随机排序 |
| `RANK()`       | 1,2,2,4... | 并列占位       |
| `DENSE_RANK()` | 1,2,2,3... | 并列不占位     |

### 问题3：如何优化一个查询缓慢的SQL语句？请说明排查步骤。

**解答：**

**排查步骤：**

| 步骤 | 操作                                  | 目的                                                                      |
| ---- | ------------------------------------- | ------------------------------------------------------------------------- |
| 1    | `EXPLAIN` 或 `SET STATISTICS TIME ON` | 查看执行计划                                                              |
| 2    | 检查是否有**全表扫描**                | 判断索引是否生效                                                          |
| 3    | 检查是否有**隐式类型转换**            | WHERE id = '123'（id是int）会导致索引失效                                 |
| 4    | 检查是否有**SELECT ***                | 只返回需要的列                                                            |
| 5    | 检查是否有**函数包裹索引列**          | WHERE YEAR(date) = 2024 应改为 date BETWEEN '2024-01-01' AND '2024-12-31' |
| 6    | 检查**数据分布**                      | 统计信息是否过期                                                          |

**常见优化手段：**
```sql
-- ❌ 慢：函数包裹索引列
SELECT * FROM Orders WHERE YEAR(CreateTime) = 2024;

-- ✅ 快：范围查询
SELECT * FROM Orders WHERE CreateTime >= '2024-01-01' AND CreateTime < '2025-01-01';

-- ❌ 慢：隐式类型转换
SELECT * FROM Orders WHERE OrderNo = 12345;  -- OrderNo是varchar

-- ✅ 快：类型匹配
SELECT * FROM Orders WHERE OrderNo = '12345';
```

### 问题4：请解释什么是索引失效的常见情况。

**解答：**

| 场景              | 错误写法                                      | 正确写法                      |
| ----------------- | --------------------------------------------- | ----------------------------- |
| 函数包裹          | `WHERE LEFT(name,3) = 'abc'`                  | `WHERE name LIKE 'abc%'`      |
| 隐式转换          | `WHERE phone = 13800138000`（phone是varchar） | `WHERE phone = '13800138000'` |
| OR条件            | `WHERE id = 1 OR name = 'test'`               | 拆分为UNION或复合索引         |
| NOT IN/NOT EXISTS | `WHERE id NOT IN (SELECT ...)`                | `NOT EXISTS`通常更好          |
| LIKE以%开头       | `WHERE name LIKE '%abc'`                      | 考虑全文索引或反向存储        |
| 索引列参与运算    | `WHERE price + 10 > 100`                      | `WHERE price > 90`            |
