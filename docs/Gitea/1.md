## Gitea 代码结构 MVC 模式总结

对于有 C# 经验的开发者，可以用 MVC 模式理解 Gitea 的架构：

### 一、MVC 对应关系

| MVC组件        | Gitea目录                 | 功能说明                                    | C#类比              |
| -------------- | ------------------------- | ------------------------------------------- | ------------------- |
| **Model**      | `/models/`                | 数据实体与数据库操作（User、Repo、Issue等） | Models文件夹/EF实体 |
| **View**       | `/templates/`             | HTML模板（.tmpl文件），服务端渲染           | Razor视图           |
| **Controller** | `/routers/` + `/modules/` | 路由定义与请求处理逻辑                      | Controllers文件夹   |

### 二、核心目录速览

- **`/routers/`** - **主入口**：定义URL路由和对应的处理函数（相当于Controller层）
  - 示例：`routers/web/repo/issue.go` 处理所有Issue相关请求

- **`/models/`** - **数据模型**：定义业务实体和数据库交互方法
  - 示例：`models/issue/issue.go` 定义Issue结构和数据库操作

- **`/modules/`** - **工具包**：通用功能模块（相当于Utils/Services类库）
  - 包含：认证、Git操作、日志等

- **`/templates/`** - **视图文件**：HTML模板，结构与路由对应
  - 示例：`templates/repo/issue/view.tmpl` 对应Issue详情页

### 三、请求流程示例（查看Issue）

以访问 `/user/repo/issues/1` 为例：

```
1. 路由解析 → routers/web/web.go 匹配路由
2. 控制器执行 → routers/web/repo/issue.go 中的 ViewIssue 函数
   - 解析参数（用户名、仓库名、Issue编号）
   - 调用 models.GetIssueByID() 获取数据
3. 数据绑定 → 将Model数据绑定到模板对象
4. 视图渲染 → templates/repo/issue/view.tmpl 生成HTML
5. 返回响应 → 最终页面返回浏览器
```

### 四、学习建议

1. **从 `/routers/` 入手**：顺着具体功能（如创建Issue）追踪代码
2. **先理解主流程**：避免过早深入 `/models/` 或 `/modules/` 细节
3. **按功能模块阅读**：例如想了解Issue评论，就看 `routers/repo/issue.go` + `models/issue/` + `templates/repo/issue/`

### 五、架构特点

- 服务端渲染（类似传统ASP.NET应用）
- 路由与处理函数分离清晰
- 业务逻辑集中在 routers 和 models
- 工具函数抽离到 modules 复用

这种分层设计使得代码组织清晰，符合"关注点分离"原则，方便扩展和维护。
