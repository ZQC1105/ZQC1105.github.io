## 1. 解释 ASP.NET Core 中的路由工作原理

路由负责将传入的 HTTP 请求映射到对应的端点（Controller、Razor Page 或委托方法）。工作流程分为两个阶段：

- **路由匹配**：路由器将请求 URL 与配置的路由模板（如 `{controller}/{action}/{id?}`）进行比较，提取路由值（controller、action、id 等），并存入 `HttpContext.Request.RouteValues`。

- **端点选择**：匹配成功后，系统选择对应的端点处理程序，并存储在 `HttpContext.GetEndpoint()` 中。

两种主要路由方式：

- **约定路由**：用于 MVC，集中配置在 `Program.cs`
- **特性路由**：用于 REST API，通过 `[Route]`、`[HttpGet]` 等属性定义

```csharp
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
```

## 2. 什么是中间件？它们按什么顺序执行？

**中间件**是组成请求处理管道的软件组件，每个中间件可以选择处理请求、传递到下一个中间件、或短路返回响应。

**执行顺序**：按照添加到 `WebApplication` 中的**添加顺序**执行请求，**相反顺序**执行响应。

```
请求 → 中间件1 → 中间件2 → 中间件3 → 核心逻辑
响应 ← 中间件1 ← 中间件2 ← 中间件3 ← 核心逻辑
```

```csharp
app.UseExceptionHandler()     // 异常处理最早
app.UseHttpsRedirection()
app.UseStaticFiles()          // 静态文件
app.UseRouting()              // 路由
app.UseAuthentication()       // 认证
app.UseAuthorization()        // 授权
app.MapControllers()          // 端点
```

## 3. 如何阻止其他中间件执行？

在中间件中不调用 `_next(context)` 即可“短路”管道，阻止后续中间件执行。

```csharp
app.Use(async (context, next) =>
{
    if (context.Request.Path.StartsWithSegments("/block"))
    {
        context.Response.StatusCode = 403;
        await context.Response.WriteAsync("Blocked");
        // 不调用 next()，后续中间件不会执行
    }
    else
    {
        await next(); // 继续执行
    }
});
```

## 4. MVC 和 Razor Pages 的区别是什么？

| 特性     | MVC                          | Razor Pages                       |
| -------- | ---------------------------- | --------------------------------- |
| 架构模式 | Model-View-Controller        | Page-based（页面模型）            |
| 文件结构 | Controller + Views 分离      | 每个页面一个 .cshtml + .cshtml.cs |
| 路由     | 基于 Controller/Action       | 基于页面文件路径                  |
| 适用场景 | REST API、复杂表单、大型应用 | 页面驱动、简单表单、CRUD 操作     |
| 处理逻辑 | Action 方法                  | OnGet/OnPost 等处理程序方法       |
| 默认推荐 | API、SPA 后端                | 传统 Web UI、页面导向应用         |

## 5. 说出 3 种创建中间件的方法

**方法一：Use 方法（内联匿名中间件）**

```csharp
app.Use(async (context, next) =>
{
    // 处理请求
    await next();
    // 处理响应
});
```

**方法二：Run 方法（终端中间件，不调用 next）**

```csharp
app.Run(async context =>
{
    await context.Response.WriteAsync("Hello World");
});
```

**方法三：传统类中间件（实现 Invoke 或 InvokeAsync 方法）**

```csharp
public class CustomMiddleware
{
    private readonly RequestDelegate _next;

    public CustomMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 请求处理逻辑
        await _next(context);
        // 响应处理逻辑
    }
}
// 注册：app.UseMiddleware<CustomMiddleware>();
```

## 6. 解释 appsettings.json 配置分层的工作原理

ASP.NET Core 使用**分层配置覆盖**机制，多个配置文件按优先级合并：

```
优先级从低到高：
1. appsettings.json              （基础配置）
2. appsettings.{Environment}.json（环境特定配置，如 Development/Production）
3. 环境变量/用户机密/命令行参数   （最高优先级）
```

**工作原理**：

- 使用 `AddJsonFile()` 按顺序加载，后加载的键值覆盖先加载的相同键
- 通过 `IConfiguration` 接口读取，支持嵌套结构（使用冒号 `:` 访问）
- 支持热重载（默认不启用，可通过 `reloadOnChange: true` 开启）

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Configuration.AddJsonFile("appsettings.json")
                     .AddJsonFile($"appsettings.{env.EnvironmentName}.json", optional: true);
```

**示例**：`appsettings.Production.json` 中的 `"ConnectionStrings"` 会覆盖 `appsettings.json` 中的同名配置。

## 7. Singleton、Scoped、Transient 服务之间有什么区别？

| 生命周期      | 创建时机                                                           | 适用场景                          | 注意事项                                                          |
| ------------- | ------------------------------------------------------------------ | --------------------------------- | ----------------------------------------------------------------- |
| **Singleton** | 第一次请求时创建，或启动时注册，**整个应用生命周期只创建一个实例** | 无状态服务、缓存、配置、工具类    | **不能依赖 Scoped 或 Transient 服务**（会导致内存泄漏或状态错误） |
| **Scoped**    | **每个 HTTP 请求**创建一个实例，请求内共享                         | DbContext、UnitOfWork、请求级缓存 | 可以依赖 Singleton 和 Transient                                   |
| **Transient** | **每次注入**都创建新实例                                           | 轻量级、无状态、短暂使用的服务    | 过度使用会增加内存和 GC 压力                                      |

```csharp
builder.Services.AddSingleton<ISingletonService, SingletonService>();
builder.Services.AddScoped<IScopedService, ScopedService>();
builder.Services.AddTransient<ITransientService, TransientService>();
```

## 8. 如何在 Singleton 服务中使用 Scoped 服务？

**问题**：Singleton 生命周期长于 Scoped，直接注入会导致 Scoped 实例被意外共享。

**解决方案**：使用 `IServiceScopeFactory` 创建作用域。

```csharp
public class SingletonService
{
    private readonly IServiceScopeFactory _scopeFactory;

    public SingletonService(IServiceScopeFactory scopeFactory)
    {
        _scopeFactory = scopeFactory;
    }

    public async Task DoWorkAsync()
    {
        using (var scope = _scopeFactory.CreateScope())
        {
            var scopedService = scope.ServiceProvider.GetRequiredService<IScopedService>();
            // 使用 scopedService，该实例仅在当前作用域内有效
        }
    }
}
```

**注意**：如果是 **BackgroundService** 或后台任务，需要手动创建作用域。对于普通请求内使用，应避免此模式。

## 9. 如何在应用程序启动和停止时执行代码？

**方法一：使用 `IHostedService` 或 `BackgroundService`（推荐）**

```csharp
public class StartupHostedService : IHostedService
{
    public Task StartAsync(CancellationToken cancellationToken)
    {
        // 启动时执行
        return Task.CompletedTask;
    }

    public Task StopAsync(CancellationToken cancellationToken)
    {
        // 停止时执行
        return Task.CompletedTask;
    }
}
// 注册：builder.Services.AddHostedService<StartupHostedService>();
```

**方法二：使用 `WebApplication` 生命周期钩子**

```csharp
var app = builder.Build();

app.Lifetime.ApplicationStarted.Register(() =>
{
    // 应用启动完成后执行
});

app.Lifetime.ApplicationStopping.Register(() =>
{
    // 应用停止前执行
});

app.Run();
```

**方法三：使用 `IApplicationLifetime`（旧版，已过时）**，建议使用 `IHostApplicationLifetime`。

## 10. 什么是 Background Service？

**BackgroundService** 是 `IHostedService` 的抽象基类，用于在后台运行**长时间运行的任务**，不阻塞主应用程序。

**典型用途**：

- 消息队列消费者（RabbitMQ、Kafka）
- 定时任务（每5分钟执行一次）
- 数据处理流水线
- 监控/清理任务

**实现示例**：

```csharp
public class TimedBackgroundService : BackgroundService
{
    private readonly ILogger<TimedBackgroundService> _logger;
    private readonly IServiceScopeFactory _scopeFactory;

    public TimedBackgroundService(ILogger<TimedBackgroundService> logger, IServiceScopeFactory scopeFactory)
    {
        _logger = logger;
        _scopeFactory = scopeFactory;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            _logger.LogInformation("后台任务运行中...");

            // 使用作用域解析 Scoped 服务
            using (var scope = _scopeFactory.CreateScope())
            {
                var dbContext = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>();
                // 执行数据库操作
            }

            await Task.Delay(TimeSpan.FromMinutes(5), stoppingToken);
        }
    }
}

// 注册
builder.Services.AddHostedService<TimedBackgroundService>();
```

**关键点**：

- `ExecuteAsync` 是核心方法，应用停止时会通过 `stoppingToken` 发出取消信号
- 需正确处理取消令牌，否则应用可能无法正常关闭
- 不能直接注入 Scoped 服务，需使用 `IServiceScopeFactory`
