## [ASP.NET Core 中的集成测试](https://learn.microsoft.com/zh-cn/aspnet/core/test/integration-tests?view=aspnetcore-8.0&pivots=xunit)

这段文字是微软官方文档中关于**集成测试与单元测试对比**的核心指导原则。让我为你详细解释其中的关键概念和最佳实践：

## 一、核心区别总结

### 单元测试 vs 集成测试

| 维度         | 单元测试               | 集成测试                         |
| ------------ | ---------------------- | -------------------------------- |
| **测试范围** | 单个组件（如类、方法） | 多个组件协同工作                 |
| **依赖处理** | 使用模拟对象（Mock）   | 使用真实组件                     |
| **测试对象** | 业务逻辑、算法         | 数据库、文件系统、网络、请求管道 |
| **运行速度** | 毫秒级，很快           | 秒级，较慢                       |
| **代码量**   | 少                     | 多                               |
| **维护成本** | 低                     | 高                               |

## 二、集成测试关注的组件

### 1. 数据库测试

```csharp
// ❌ 错误：为每个业务方法都写集成测试
[Fact]
public async Task CreateUser_IntegrationTest()
{
    // 真实的数据库操作
    var user = new User { Name = "John" };
    await _dbContext.Users.AddAsync(user);
    await _dbContext.SaveChangesAsync();

    var savedUser = await _dbContext.Users.FindAsync(user.Id);
    Assert.NotNull(savedUser);
}

[Fact]
public async Task UpdateUser_IntegrationTest() { /* 类似代码 */ }
[Fact]
public async Task DeleteUser_IntegrationTest() { /* 类似代码 */ }

// ✅ 正确：集中测试数据库 CRUD 操作
public class DatabaseIntegrationTests
{
    // 只测试数据库的基本操作
    [Fact]
    public async Task Database_CanCreateReadUpdateDelete()
    {
        // Create
        var user = new User { Name = "John" };
        _dbContext.Users.Add(user);
        await _dbContext.SaveChangesAsync();

        // Read
        var readUser = await _dbContext.Users.FindAsync(user.Id);
        Assert.Equal("John", readUser.Name);

        // Update
        readUser.Name = "Jane";
        await _dbContext.SaveChangesAsync();
        var updatedUser = await _dbContext.Users.FindAsync(user.Id);
        Assert.Equal("Jane", updatedUser.Name);

        // Delete
        _dbContext.Users.Remove(updatedUser);
        await _dbContext.SaveChangesAsync();
        var deletedUser = await _dbContext.Users.FindAsync(user.Id);
        Assert.Null(deletedUser);
    }
}
```

### 2. 业务逻辑使用单元测试

## 三、选择合适的测试类型

### 决策树

```
需要测试某个功能
    ↓
是否涉及数据库/文件系统/网络？
    ↓
    是 → 是否为核心基础设施操作？
        ↓
        是 → 使用集成测试（但只测试一次）
        否 → 使用单元测试（Mock 依赖）
    ↓
    否 → 使用单元测试
```

### 实际示例

```csharp
// 场景1：用户注册功能
public class UserRegistrationService
{
    private readonly IUserRepository _userRepo;
    private readonly IEmailService _emailService;

    public async Task<bool> RegisterUser(UserDto userDto)
    {
        // 1. 验证输入（业务逻辑）
        if (string.IsNullOrEmpty(userDto.Email))
            return false;

        // 2. 检查用户是否存在（数据库操作）
        if (await _userRepo.ExistsByEmail(userDto.Email))
            return false;

        // 3. 保存用户（数据库操作）
        var user = new User { Email = userDto.Email };
        await _userRepo.AddAsync(user);

        // 4. 发送欢迎邮件（外部服务）
        await _emailService.SendWelcomeEmail(userDto.Email);

        return true;
    }
}

// 集成测试：只测试核心流程一次
public class UserRegistrationIntegrationTests
{
    [Fact]
    public async Task RegisterUser_EndToEnd_Success()
    {
        // 使用真实数据库和邮件服务（或测试专用）
        var factory = new WebApplicationFactory<Program>();
        var client = factory.CreateClient();

        var response = await client.PostAsJsonAsync("/api/users/register",
            new { Email = "test@example.com" });

        Assert.Equal(HttpStatusCode.OK, response.StatusCode);

        // 验证数据库中有记录
        var dbContext = factory.Services.GetRequiredService<AppDbContext>();
        var user = await dbContext.Users.FirstOrDefaultAsync(u => u.Email == "test@example.com");
        Assert.NotNull(user);
    }
}

// 单元测试：测试各种业务规则
public class UserRegistrationUnitTests
{
    [Fact]
    public async Task RegisterUser_InvalidEmail_ReturnsFalse()
    {
        // Mock 所有依赖
        var mockRepo = new Mock<IUserRepository>();
        var mockEmail = new Mock<IEmailService>();
        var service = new UserRegistrationService(mockRepo.Object, mockEmail.Object);

        // 测试业务规则
        var result = await service.RegisterUser(new UserDto { Email = "" });

        Assert.False(result);
        mockRepo.Verify(r => r.AddAsync(It.IsAny<User>()), Times.Never);
    }

    [Fact]
    public async Task RegisterUser_ExistingEmail_ReturnsFalse()
    {
        var mockRepo = new Mock<IUserRepository>();
        mockRepo.Setup(r => r.ExistsByEmail("existing@example.com"))
                .ReturnsAsync(true);

        var service = new UserRegistrationService(mockRepo.Object, Mock.Of<IEmailService>());

        var result = await service.RegisterUser(new UserDto { Email = "existing@example.com" });

        Assert.False(result);
        mockRepo.Verify(r => r.AddAsync(It.IsAny<User>()), Times.Never);
    }
}
```

## 四、集成测试的最佳实践

### 1. 集中测试基础设施

```csharp
// ✅ 好的做法：一个测试类测试所有数据库操作
public class DatabaseIntegrationTests
{
    [Fact]
    public async Task UserRepository_CrudOperations_Success()
    {
        // Create
        // Read
        // Update
        // Delete
    }

    [Fact]
    public async Task OrderRepository_CrudOperations_Success()
    {
        // Create
        // Read
        // Update
        // Delete
    }
}

// ❌ 不好的做法：每个业务场景都测试数据库
public class OrderServiceTests
{
    [Fact]
    public async Task CreateOrder_WithValidData_SavesToDatabase() { }

    [Fact]
    public async Task CreateOrder_WithDiscount_SavesToDatabase() { }

    [Fact]
    public async Task CreateOrder_WithMultipleItems_SavesToDatabase() { }

    // 这些都是重复测试数据库功能
}
```

### 2. 使用测试专用环境

```csharp
public class CustomWebApplicationFactory : WebApplicationFactory<Program>
{
    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        builder.UseEnvironment("Testing"); // 测试专用环境

        builder.ConfigureServices(services =>
        {
            // 替换真实数据库为测试数据库
            var descriptor = services.SingleOrDefault(
                d => d.ServiceType == typeof(DbContextOptions<AppDbContext>));

            if (descriptor != null)
                services.Remove(descriptor);

            // 使用内存数据库进行测试
            services.AddDbContext<AppDbContext>(options =>
                options.UseInMemoryDatabase("TestDb"));
        });
    }
}
```

### 3. 测试金字塔原则

```
        /\
       /  \     集成测试（少量）
      /    \    - 端到端流程
     /------\   - 关键路径
    /        \
   /__________\ 单元测试（大量）
                - 业务逻辑
                - 边界条件
                - 异常处理
```

## 五、实际决策示例

### 场景：文件上传功能

```csharp
public class FileUploadService
{
    private readonly IFileSystem _fileSystem;
    private readonly IFileValidator _validator;

    public async Task<bool> UploadFile(Stream fileStream, string fileName)
    {
        // 1. 验证文件（业务逻辑）
        if (!_validator.IsValid(fileName))
            return false;

        // 2. 保存文件（文件系统操作）
        await _fileSystem.SaveAsync(fileStream, fileName);

        // 3. 记录日志（数据库操作）
        await _logger.LogAsync($"File {fileName} uploaded");

        return true;
    }
}

// 决策：
// - 文件验证逻辑 → 单元测试
// - 文件保存 + 日志记录 → 集成测试（只测一次）
// - 完整上传流程 → 集成测试（只测关键路径）

public class FileValidationTests
{
    [Fact]
    public void IsValid_InvalidExtension_ReturnsFalse()
    {
        // 单元测试：测试验证逻辑
        var validator = new FileValidator();
        Assert.False(validator.IsValid("virus.exe"));
    }
}

public class FileUploadIntegrationTests
{
    [Fact]
    public async Task UploadFile_EndToEnd_Success()
    {
        // 集成测试：测试完整流程
        var factory = new CustomWebApplicationFactory();
        var client = factory.CreateClient();

        using var content = new MultipartFormDataContent();
        content.Add(new StreamContent(GetTestFileStream()), "file", "test.txt");

        var response = await client.PostAsync("/api/files/upload", content);

        Assert.Equal(HttpStatusCode.OK, response.StatusCode);

        // 验证文件已保存
        var fileSystem = factory.Services.GetRequiredService<IFileSystem>();
        Assert.True(fileSystem.Exists("test.txt"));

        // 验证日志已记录
        var dbContext = factory.Services.GetRequiredService<AppDbContext>();
        Assert.Contains(dbContext.Logs, l => l.Message.Contains("test.txt"));
    }
}
```

## 总结关键点

1. **优先使用单元测试**：能用单元测试覆盖的行为就不要用集成测试
2. **集成测试要集中**：不要为每个业务场景都写集成测试，而是集中测试基础设施组件
3. **测试金字塔**：大量单元测试 + 少量集成测试 + 极少端到端测试
4. **真实组件 vs 模拟**：集成测试使用真实组件，单元测试使用模拟对象
5. **关注成本**：集成测试运行慢、维护成本高，只测试最重要的场景

这样可以在保证代码质量的同时，维持高效的测试套件和快速的开发反馈循环。
