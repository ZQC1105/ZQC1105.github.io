## 21. 如何使用 EF Core 迁移进行数据种子（Data Seeding）？

EF Core 提供三种数据种子方式：**模型种子数据**（迁移的一部分）、**自定义初始化逻辑**、**手动 SQL 脚本**。

**方法一：模型种子数据（推荐用于静态/引用数据）**

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 种子单一实体
    modelBuilder.Entity<Blog>().HasData(
        new Blog { Id = 1, Name = "Tech Blog", CreatedAt = new DateTime(2024, 1, 1) },
        new Blog { Id = 2, Name = "Food Blog", CreatedAt = new DateTime(2024, 1, 2) }
    );

    // 种子相关实体（需按依赖顺序）
    modelBuilder.Entity<Post>().HasData(
        new Post { Id = 1, Title = "First Post", BlogId = 1, Content = "Hello" },
        new Post { Id = 2, Title = "Second Post", BlogId = 1, Content = "World" }
    );

    // 种子枚举/查找表
    modelBuilder.Entity<OrderStatus>().HasData(
        Enum.GetValues(typeof(StatusEnum))
            .Cast<StatusEnum>()
            .Select(e => new OrderStatus { Id = (int)e, Name = e.ToString() })
    );
}
```

**方法二：自定义迁移操作（复杂逻辑）**

```csharp
// 创建空迁移：dotnet ef migrations add SeedData
public partial class SeedData : Migration
{
    protected override void Up(MigrationBuilder migrationBuilder)
    {
        // 插入数据
        migrationBuilder.InsertData(
            table: "Users",
            columns: new[] { "Id", "Name", "Email" },
            values: new object[,]
            {
                { 1, "Admin", "admin@example.com" },
                { 2, "User1", "user1@example.com" }
            });

        // 使用 SQL 处理复杂逻辑
        migrationBuilder.Sql(@"
            IF NOT EXISTS (SELECT 1 FROM [Roles] WHERE [Name] = 'Admin')
            BEGIN
                INSERT INTO [Roles] ([Name]) VALUES ('Admin')
            END
        ");

        // 更新现有数据
        migrationBuilder.Sql("UPDATE [Products] SET [IsActive] = 1 WHERE [IsActive] IS NULL");
    }

    protected override void Down(MigrationBuilder migrationBuilder)
    {
        migrationBuilder.DeleteData(table: "Users", keyColumn: "Id", keyValues: new object[] { 1, 2 });
        migrationBuilder.Sql("DELETE FROM [Roles] WHERE [Name] = 'Admin'");
    }
}
```

**方法三：自定义 DbContext 初始化（开发/测试环境）**

```csharp
public static class DbInitializer
{
    public static async Task InitializeAsync(IServiceProvider services)
    {
        using var scope = services.CreateScope();
        var context = scope.ServiceProvider.GetRequiredService<AppDbContext>();

        {
            var categories = new[]

                new Category { Name = "Electronics" },
                new Category { Name = "Books" }
            };

        }
    }
}

// Program.cs

{

}
```

## 22. 客户端评估（Client-side）与服务端评估（Server-side）的区别

| 特性         | 服务端评估                   | 客户端评估               |
| ------------ | ---------------------------- | ------------------------ |
| **执行位置** | 数据库服务器                 | .NET 应用程序内存        |
| **性能**     | 快（利用索引、减少数据传输） | 慢（需传输大量数据）     |
| **功能支持** | 受限于数据库函数             | 完整 .NET 功能           |
| **内存使用** | 低                           | 高（全部数据加载到内存） |
| **网络传输** | 仅返回结果                   | 传输所有原始数据         |

**服务端评估（正确）**：

```csharp
// ✅ 转换为 SQL WHERE 子句
var products = context.Products
    .Where(p => p.Price > 100 && p.CreatedAt > DateTime.Now.AddDays(-30))
    .ToList();
// SQL: WHERE [Price] > 100 AND [CreatedAt] > '2024-01-01'

// ✅ 聚合函数在数据库执行
var avgPrice = context.Products.Average(p => p.Price);
// SQL: SELECT AVG([Price]) FROM Products

// ✅ 标准字符串函数
var names = context.Users
    .Where(u => u.Name.StartsWith("A") && u.Name.Contains("test"))
    .ToList();
// SQL: WHERE [Name] LIKE N'A%' AND [Name] LIKE N'%test%'
```

**客户端评估（问题）**：

```csharp
// ⚠️ 自定义方法无法翻译
var result = context.Products
    .Where(p => MyCustomMethod(p.Price))
    .ToList();  // 警告：可能在客户端评估

// ❌ 严重性能问题：全表传输到客户端
var badQuery = context.Products
    .Where(p => Regex.IsMatch(p.Name, "^[A-Z].*"))
    .ToList();
// 先 SELECT * FROM Products（所有行），然后在内存中过滤

// ❌ 嵌套集合导致多次客户端评估
var orders = context.Orders.ToList();  // 全部加载
var filtered = orders.Where(o => o.Items.Sum(i => i.Quantity) > 10);
```

**强制客户端评估（EF Core 6+ 会警告）**：

```csharp
// 配置客户端评估行为
protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
{
    optionsBuilder
        .UseSqlServer(connectionString)
        .ConfigureWarnings(warnings =>
            warnings.Throw(RelationalEventId.QueryClientEvaluationWarning));
}

// 显式切换到客户端（使用 AsEnumerable）
var clientEval = context.Products
    .Where(p => p.Price > 100)
    .AsEnumerable()  // 从此处切换到客户端
    .Where(p => Regex.IsMatch(p.Name, "^A.*"))
    .ToList();
```

## 24. 如何设计基于 DDD 的 EF Core 聚合根（Aggregate Root）？

**聚合根核心原则**：

- 聚合根是唯一入口，外部只能通过聚合根访问其内部实体
- 内部状态通过**行为方法**修改，而非直接暴露 setter
- 使用**私有构造函数**和**只读字段**

**完整示例**：

```csharp
// 值对象
public class Address : ValueObject
{
    public string Street { get; private set; }
    public string City { get; private set; }
    public string PostalCode { get; private set; }

    public Address(string street, string city, string postalCode)
    {
        Street = street;
        City = city;
        PostalCode = postalCode;
    }

    protected override IEnumerable<object> GetEqualityComponents()
    {
        yield return Street;
        yield return City;
        yield return PostalCode;
    }
}

// 实体（聚合内）
public class OrderItem
{
    public int Id { get; private set; }
    public string ProductName { get; private set; }
    public int Quantity { get; private set; }
    public decimal UnitPrice { get; private set; }

    internal OrderItem(string productName, int quantity, decimal unitPrice)
    {
        ProductName = productName;
        Quantity = quantity;
        UnitPrice = unitPrice;
    }

    public decimal GetTotal() => Quantity * UnitPrice;

    internal void UpdateQuantity(int newQuantity) => Quantity = newQuantity;
}

// 聚合根
public class Order : IAggregateRoot
{
    private readonly List<OrderItem> _items = new();

    public int Id { get; private set; }
    public string OrderNumber { get; private set; }
    public DateTime CreatedAt { get; private set; }
    public OrderStatus Status { get; private set; }
    public Address ShippingAddress { get; private set; }
    public IReadOnlyCollection<OrderItem> Items => _items.AsReadOnly();
    public decimal TotalAmount => _items.Sum(i => i.GetTotal());

    // 私有构造函数（EF Core 需要）
    private Order() { }

    // 工厂方法
    public static Order Create(string orderNumber, Address shippingAddress)
    {
        return new Order
        {
            OrderNumber = orderNumber,
            ShippingAddress = shippingAddress,
            CreatedAt = DateTime.UtcNow,
            Status = OrderStatus.Pending
        };
    }

    // 行为方法
    public void AddItem(string productName, int quantity, decimal unitPrice)
    {
        if (Status != OrderStatus.Pending)
            throw new InvalidOperationException("只能向待处理订单添加商品");

        var existing = _items.FirstOrDefault(i => i.ProductName == productName);
        if (existing != null)
            existing.UpdateQuantity(existing.Quantity + quantity);
        else
            _items.Add(new OrderItem(productName, quantity, unitPrice));
    }

    public void RemoveItem(int itemId)
    {
        var item = _items.FirstOrDefault(i => i.Id == itemId);
        if (item != null)
            _items.Remove(item);
    }

    public void Submit()
    {
        if (!_items.Any())
            throw new InvalidOperationException("订单不能为空");

        Status = OrderStatus.Submitted;
    }

    public void Cancel()
    {
        if (Status == OrderStatus.Shipped)
            throw new InvalidOperationException("已发货订单不能取消");

        Status = OrderStatus.Cancelled;
    }
}

// EF Core 配置
public class OrderConfiguration : IEntityTypeConfiguration<Order>
{
    public void Configure(EntityTypeBuilder<Order> builder)
    {
        builder.ToTable("Orders");
        builder.HasKey(o => o.Id);

        // 值对象映射为拥有类型
        builder.OwnsOne(o => o.ShippingAddress, address =>
        {
            address.Property(a => a.Street).HasColumnName("ShippingStreet").HasMaxLength(200);
            address.Property(a => a.City).HasColumnName("ShippingCity").HasMaxLength(100);
            address.Property(a => a.PostalCode).HasColumnName("ShippingPostalCode").HasMaxLength(20);
        });

        // 枚举映射为字符串
        builder.Property(o => o.Status)
            .HasConversion<string>()
            .HasMaxLength(20);

        // 私有集合字段映射
        builder.HasMany(o => o.Items)
            .WithOne()
            .HasForeignKey("OrderId")
            .OnDelete(DeleteBehavior.Cascade);

        // 忽略非映射属性
        builder.Ignore(o => o.TotalAmount);

        // 配置私有字段访问（如果需要）
        builder.Metadata.FindNavigation(nameof(Order.Items))
            .SetPropertyAccessMode(PropertyAccessMode.Field);
    }
}
```

## 26. 减少 EF Core 中 N+1 查询的策略

## 27. 编译查询（Compiled Queries）如何提升 EF Core 性能？

**编译查询** 将 LINQ 查询表达式树预编译为委托，避免每次执行时的解析和翻译开销，适合**高频重复查询**。

**性能提升**：

- 首次执行：编译开销（约 10-20ms）
- 后续执行：直接调用委托（约 0.1-0.5ms）
- 高频场景可提升 **5-10 倍**性能

**异步编译查询**：

```csharp
// 定义编译查询（静态字段）
private static readonly Func<AppDbContext, int, Task<Product?>> _getProductById =
    EF.CompileAsyncQuery((AppDbContext ctx, int id) =>
        ctx.Products
            .AsNoTracking()
            .Include(p => p.Category)
            .FirstOrDefault(p => p.Id == id));

// 使用
public async Task<Product?> GetProductAsync(int id)
{
    return await _getProductById(_context, id);
}

// 带多个参数
private static readonly Func<AppDbContext, string, decimal, Task<List<Product>>> _searchProducts =
    EF.CompileAsyncQuery((AppDbContext ctx, string nameContains, decimal minPrice) =>
        ctx.Products
            .Where(p => p.Name.Contains(nameContains) && p.Price >= minPrice)
            .OrderBy(p => p.Price)
            .Take(50)
            .AsNoTracking()
            .ToList());
```

**同步编译查询**：

```csharp
private static readonly Func<AppDbContext, int, Product?> _getProductByIdSync =
    EF.CompileQuery((AppDbContext ctx, int id) =>
        ctx.Products.AsNoTracking().FirstOrDefault(p => p.Id == id));

public Product? GetProduct(int id) => _getProductByIdSync(_context, id);
```

**复杂编译查询**：

```csharp
// 包含投影
private static readonly Func<AppDbContext, int, Task<ProductDto?>> _getProductDto =
    EF.CompileAsyncQuery((AppDbContext ctx, int id) =>
        ctx.Products
            .Where(p => p.Id == id)
            .Select(p => new ProductDto
            {
                Id = p.Id,
                Name = p.Name,

                CategoryName = p.Category.Name
            })
            .FirstOrDefault());

// 分页查询

    EF.CompileAsyncQuery((AppDbContext ctx, int skip, int take) =>
        ctx.Products
            .OrderBy(p => p.Id)
            .Skip(skip)
            .Take(take)
            .AsNoTracking()
            .ToList());
```

```csharp

// ✅ 使用参数

    ctx.Products.Where(p => p.Price > minPrice));
```

## 28. AutoInclude 会带来什么问题？何时避免使用？

**AutoInclude** 在 EF Core 5+ 中配置，使导航属性在**每次查询**时自动加载。

**配置方式**：

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Blog>()
        .Navigation(b => b.Posts)
        .AutoInclude();

    modelBuilder.Entity<Post>()
        .Navigation(p => p.Comments)
        .AutoInclude();
}

// 每次查询 Blog 都会自动 Include Posts
var blogs = context.Blogs.ToList();  // 自动加载 Posts
```

**问题与风险**：

| 问题           | 说明                          | 示例                                       |
| -------------- | ----------------------------- | ------------------------------------------ |
| **性能下降**   | 总是加载不需要的数据          | 只想要 Blog 名称，却加载了所有 Posts       |
| **N+1 加剧**   | 多层 AutoInclude 导致大量数据 | Blog → Posts → Comments → Author           |
| **笛卡尔爆炸** | 多层级联导致数据膨胀          | 1 Blog → 100 Posts → 10 Comments = 1000 行 |
| **无法优化**   | 无法按查询选择加载策略        | 简单查询和复杂查询无法区分                 |
| **内存占用**   | 大量无关数据消耗内存          | 报表查询加载了所有关联                     |

**何时避免**：

```csharp
// ❌ 避免：列表页面不需要完整关联数据
var blogList = context.Blogs.ToList();  // 自动加载了 Posts，但列表页面不需要

// ❌ 避免：高频率调用的简单查询
public async Task<bool> BlogExistsAsync(string name)
{
    // 这个查询只需要检查存在性，不需要 Posts
    return await context.Blogs.AnyAsync(b => b.Name == name);
}

// ❌ 避免：报表/聚合查询
var blogCount = context.Blogs.Count();  // 不需要加载任何关联
```

**解决方案**：

```csharp
// 1. 按需禁用 AutoInclude
var blogs = context.Blogs
    .IgnoreAutoIncludes()  // 禁用所有 AutoInclude
    .ToList();

// 2. 手动控制加载（不使用 AutoInclude）
modelBuilder.Entity<Blog>()
    .Navigation(b => b.Posts)
    .AutoInclude(false);  // 不自动加载

// 3. 使用投影替代 Include
var blogInfos = context.Blogs
    .Select(b => new BlogInfo
    {
        Id = b.Id,
        Name = b.Name,
        PostCount = b.Posts.Count()  // 只计数，不加载全部
    })
    .ToList();

// 4. 条件性 Include
var blog = await context.Blogs
    .Include(b => needPosts ? b.Posts : null)  // 条件 Include
    .FirstOrDefaultAsync(b => b.Id == id);
```

## 29. 如何在 EF Core 中实现软删除（Soft Delete）？

**软删除** 标记数据为"已删除"而不实际从数据库中移除。

**方法一：全局查询过滤器（推荐）**

```csharp
// 实体基类
public interface ISoftDelete
{
    bool IsDeleted { get; set; }
    DateTime? DeletedAt { get; set; }
    string? DeletedBy { get; set; }
}

public class Product : ISoftDelete
{
    public int Id { get; set; }
    public string Name { get; set; }
    public bool IsDeleted { get; set; }
    public DateTime? DeletedAt { get; set; }
    public string? DeletedBy { get; set; }
}

// DbContext 配置
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 全局软删除过滤器
    modelBuilder.Entity<Product>().HasQueryFilter(p => !p.IsDeleted);
    modelBuilder.Entity<Order>().HasQueryFilter(o => !o.IsDeleted);
    modelBuilder.Entity<User>().HasQueryFilter(u => !u.IsDeleted);
}

// 软删除方法
public async Task SoftDeleteAsync<T>(int id, string deletedBy) where T : class, ISoftDelete
{
    var entity = await _context.Set<T>().FirstOrDefaultAsync(e => e.Id == id);
    if (entity != null)
    {
        entity.IsDeleted = true;
        entity.DeletedAt = DateTime.UtcNow;
        entity.DeletedBy = deletedBy;
        await _context.SaveChangesAsync();
    }
}

// 覆盖过滤器查询已删除数据
var deletedProducts = await _context.Products
    .IgnoreQueryFilters()
    .Where(p => p.IsDeleted)
    .ToListAsync();
```

**方法二：使用 SaveChanges 拦截器（自动处理）**

```csharp
public class SoftDeleteInterceptor : SaveChangesInterceptor
{
    private readonly IHttpContextAccessor _httpContextAccessor;

    public SoftDeleteInterceptor(IHttpContextAccessor httpContextAccessor)
    {
        _httpContextAccessor = httpContextAccessor;
    }

    public override InterceptionResult<int> SavingChanges(DbContextEventData eventData, InterceptionResult<int> result)
    {
        ApplySoftDelete(eventData.Context);
        return base.SavingChanges(eventData, result);
    }

    public override ValueTask<InterceptionResult<int>> SavingChangesAsync(DbContextEventData eventData, InterceptionResult<int> result, CancellationToken ct = default)
    {
        ApplySoftDelete(eventData.Context);
        return base.SavingChangesAsync(eventData, result, ct);
    }

    private void ApplySoftDelete(DbContext? context)
    {
        if (context == null) return;

        var entries = context.ChangeTracker.Entries()
            .Where(e => e.State == EntityState.Deleted && e.Entity is ISoftDelete);

        foreach (var entry in entries)
        {
            entry.State = EntityState.Modified;
            ((ISoftDelete)entry.Entity).IsDeleted = true;
            ((ISoftDelete)entry.Entity).DeletedAt = DateTime.UtcNow;
            ((ISoftDelete)entry.Entity).DeletedBy = _httpContextAccessor.HttpContext?.User?.Identity?.Name;
        }
    }
}

// 注册
builder.Services.AddSingleton<SoftDeleteInterceptor>();
builder.Services.AddDbContext<AppDbContext>((sp, options) =>
    options.UseSqlServer(connectionString)
           .AddInterceptors(sp.GetRequiredService<SoftDeleteInterceptor>()));
```

**方法三：使用原始 SQL 批量软删除**

```csharp
public async Task<int> BatchSoftDeleteAsync(string productNameContains)
{
    return await _context.Products
        .Where(p => p.Name.Contains(productNameContains) && !p.IsDeleted)
        .ExecuteUpdateAsync(setters => setters
            .SetProperty(p => p.IsDeleted, true)
            .SetProperty(p => p.DeletedAt, DateTime.UtcNow)
            .SetProperty(p => p.DeletedBy, _currentUser));
}
```

## 30. TPH、TPT 和 TPC 继承映射的区别

| 映射策略                          | 表结构                 | 性能            | 查询复杂度 | 适用场景                             |
| --------------------------------- | ---------------------- | --------------- | ---------- | ------------------------------------ |
| **TPH** (Table-per-Hierarchy)     | 单表，使用**鉴别器列** | 最快（无 JOIN） | 简单       | 子类差异小，多数查询涉及所有类型     |
| **TPT** (Table-per-Type)          | 基类表 + 每个子类表    | 慢（需 JOIN）   | 复杂       | 子类差异大，字段多，符合数据库范式   |
| **TPC** (Table-per-Concrete-Type) | 每个具体类独立表       | 中等（UNION）   | 复杂       | EF Core 7+，子类完全独立，无多态查询 |

**TPH（默认，单表）**：

```csharp
public abstract class Person
{
    public int Id { get; set; }
    public string Name { get; set; }
}

public class Student : Person
{
    public string StudentNumber { get; set; }
    public double GPA { get; set; }
}

public class Teacher : Person
{
    public string EmployeeNumber { get; set; }
    public decimal Salary { get; set; }
}

// 生成的单表：Persons
// Id, Name, StudentNumber, GPA, EmployeeNumber, Salary, Discriminator

// 配置
modelBuilder.Entity<Person>()
    .HasDiscriminator<string>("PersonType")
    .HasValue<Student>("Student")
    .HasValue<Teacher>("Teacher");
```

**TPT（每类型一表）**：

```csharp
modelBuilder.Entity<Person>().ToTable("Persons");
modelBuilder.Entity<Student>().ToTable("Students");
modelBuilder.Entity<Teacher>().ToTable("Teachers");

// 表结构：
// Persons: Id, Name
// Students: Id, StudentNumber, GPA
// Teachers: Id, EmployeeNumber, Salary

// 查询 Student 会 JOIN Persons 和 Students
```

**TPC（每具体类一表，EF Core 7+）**：

```csharp
modelBuilder.Entity<Person>().UseTpcMappingStrategy();
modelBuilder.Entity<Student>().ToTable("Students");
modelBuilder.Entity<Teacher>().ToTable("Teachers");

// 表结构（无 Persons 表）：
// Students: Id, Name, StudentNumber, GPA
// Teachers: Id, Name, EmployeeNumber, Salary

// 注意：Id 需要手动管理或使用序列
modelBuilder.Entity<Student>().Property(s => s.Id).UseIdentityColumn();
modelBuilder.Entity<Teacher>().Property(t => t.Id).UseIdentityColumn();
```

**选择指南**：

```csharp
// TPH - 大多数场景
// 优点：查询快，简单
// 缺点：有可为 NULL 的列
if (多数查询使用基类或查询所有子类) → TPH

// TPT - 字段多且子类差异大
// 优点：规范化，无 NULL 列
// 缺点：JOIN 性能开销
if (子类有大量特有字段 && 查询通常只针对单一子类) → TPT

// TPC - EF Core 7+ 新选择
// 优点：无 JOIN，无 NULL 列
// 缺点：不支持外键约束，Id 管理复杂
if (子类完全独立 && 很少跨子类查询) → TPC
```
