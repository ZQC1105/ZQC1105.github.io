## 21. 解释 JWT Token 的工作原理

**JWT (JSON Web Token)** 是一种紧凑的、自包含的令牌格式，用于在各方之间安全传输信息。

**JWT 结构**：由三部分组成，用点号 `.` 分隔

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjMiLCJuYW1lIjoiSmFuZSJ9.sflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

| 部分      | 名称 | 说明                                      |
| --------- | ---- | ----------------------------------------- |
| Header    | 头部 | 包含签名算法（如 HS256）和令牌类型        |
| Payload   | 载荷 | 包含 Claims（用户信息、权限、过期时间等） |
| Signature | 签名 | 用于验证令牌未被篡改                      |

**工作流程**：

```
1. 登录请求
   用户 ──(用户名/密码)──> 服务器

2. 验证并签发 JWT
   服务器 ──(生成 JWT)──> 用户

3. 后续请求携带 JWT
   用户 ──(Authorization: Bearer <JWT>)──> 服务器

4. 服务器验证 JWT
   - 检查签名是否有效
   - 检查是否过期
   - 从 JWT 中读取用户信息（无需查数据库）
```

**ASP.NET Core 配置示例**：

```csharp
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidIssuer = "your-issuer",
            ValidateAudience = true,
            ValidAudience = "your-audience",
            ValidateLifetime = true,
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes("your-secret-key"))
        };
    });
```

**生成 JWT**：

```csharp
var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes("secret-key"));
var credentials = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

var token = new JwtSecurityToken(
    issuer: "your-issuer",
    audience: "your-audience",
    claims: new[] { new Claim(ClaimTypes.Name, "username") },
    expires: DateTime.Now.AddHours(1),
    signingCredentials: credentials);

var jwt = new JwtSecurityTokenHandler().WriteToken(token);
```

## 22. 解释 Refresh Token 及其工作原理

**Refresh Token** 是一种用于获取新 Access Token 的长期凭证，用于解决 Access Token 短期过期的问题。

**为什么需要 Refresh Token？**

- Access Token 短期有效（如 15 分钟），减少被盗用风险
- 用户无需频繁重新登录
- Refresh Token 可以撤销，Access Token 不能

**工作原理**：

```
登录时：
服务器 ──(返回 Access Token + Refresh Token)──> 客户端
                ├── Access Token  (15分钟过期)
                └── Refresh Token (7天过期，存储在安全位置)

Access Token 过期后：
客户端 ──(发送 Refresh Token 到 /refresh 端点)──> 服务器

服务器验证 Refresh Token：
├── 有效 → 签发新的 Access Token（和新的 Refresh Token）
└── 无效/过期/撤销 → 要求重新登录
```

**实现示例**：

```csharp
// 存储 Refresh Token 的实体
public class RefreshToken
{
    public int Id { get; set; }
    public string UserId { get; set; }
    public string Token { get; set; }
    public DateTime ExpiryDate { get; set; }
    public bool IsRevoked { get; set; }
}

// 登录时生成两个 Token
[HttpPost("login")]
public async Task<IActionResult> Login(LoginModel model)
{
    var user = await _userService.ValidateAsync(model.Username, model.Password);

    var accessToken = GenerateAccessToken(user);
    var refreshToken = GenerateRefreshToken();

    // 保存 Refresh Token 到数据库
    await _refreshTokenService.SaveAsync(user.Id, refreshToken, DateTime.UtcNow.AddDays(7));

    return Ok(new { AccessToken = accessToken, RefreshToken = refreshToken });
}

// 刷新端点
[HttpPost("refresh")]
public async Task<IActionResult> Refresh([FromBody] RefreshRequest request)
{
    var storedToken = await _refreshTokenService.GetByTokenAsync(request.RefreshToken);

    if (storedToken == null || storedToken.ExpiryDate < DateTime.UtcNow || storedToken.IsRevoked)
        return Unauthorized("Invalid refresh token");

    var user = await _userService.GetByIdAsync(storedToken.UserId);
    var newAccessToken = GenerateAccessToken(user);
    var newRefreshToken = GenerateRefreshToken();

    // 撤销旧 Refresh Token，保存新 Token（Refresh Token Rotation）
    await _refreshTokenService.RevokeAsync(storedToken.Id);
    await _refreshTokenService.SaveAsync(user.Id, newRefreshToken, DateTime.UtcNow.AddDays(7));

    return Ok(new { AccessToken = newAccessToken, RefreshToken = newRefreshToken });
}
```

**安全最佳实践**：

- Refresh Token 应存储在 **HttpOnly Cookie** 或安全存储中
- 使用 **Refresh Token Rotation**（每次刷新发放新 Token，旧 Token 失效）
- 检测 Refresh Token 重用 → 撤销所有 Token 并强制重新登录

**方法二：基于资源的权限检查（动态权限）**

```csharp
// 实现资源授权处理器
public class ProductAuthorizationHandler : AuthorizationHandler<ResourceOperationRequirement, Product>
{
    protected override Task HandleRequirementAsync(AuthorizationHandlerContext context,
        ResourceOperationRequirement requirement, Product resource)
    {
        var userId = context.User.FindFirstValue(ClaimTypes.NameIdentifier);

        // 检查用户是否有权访问该资源
        if (requirement.Operation == "View" && resource.IsPublic)
            context.Succeed(requirement);

        if (requirement.Operation == "Edit" && resource.OwnerId == userId)
            context.Succeed(requirement);

        if (context.User.IsInRole("Admin"))
            context.Succeed(requirement);

        return Task.CompletedTask;
    }
}

// 在 Controller 中使用
[HttpGet("{id}")]
public async Task<IActionResult> GetProduct(int id)
{
    var product = await _productService.GetAsync(id);

    var authResult = await _authorizationService.AuthorizeAsync(
        User, product, new ResourceOperationRequirement("View"));

    if (!authResult.Succeeded)
        return Forbid();

    return Ok(product);
}
```

## 24. HostedService 用于什么？

**IHostedService** 和 **BackgroundService** 用于在 ASP.NET Core 应用的后台运行**长时间运行的任务**，这些任务与 HTTP 请求生命周期无关。

**主要用途**：

| 场景             | 示例                              |
| ---------------- | --------------------------------- |
| **定时任务**     | 每5分钟清理过期数据、发送提醒邮件 |
| **消息队列消费** | 从 RabbitMQ/Kafka 读取消息并处理  |
| **数据同步**     | 定期从外部 API 同步数据           |
| **监控告警**     | 监控系统健康状态并告警            |
| **缓存预热**     | 应用启动时加载数据到缓存          |
| **后台计算**     | 处理队列中的计算任务              |

**简单示例**：

```csharp
public class CleanupService : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly ILogger<CleanupService> _logger;

    public CleanupService(IServiceScopeFactory scopeFactory, ILogger<CleanupService> logger)
    {
        _scopeFactory = scopeFactory;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                using var scope = _scopeFactory.CreateScope();
                var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();

                // 删除30天前的过期记录
                var cutoff = DateTime.UtcNow.AddDays(-30);
                var deleted = await dbContext.TempData
                    .Where(x => x.CreatedAt < cutoff)
                    .ExecuteDeleteAsync(stoppingToken);

                _logger.LogInformation("清理了 {Count} 条过期记录", deleted);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "清理任务失败");
            }

            await Task.Delay(TimeSpan.FromHours(24), stoppingToken);
        }
    }
}
```

## 25. PeriodicTimer 和 await Task.Delay() 的区别

| 特性         | PeriodicTimer                                      | Task.Delay + 循环                  |
| ------------ | -------------------------------------------------- | ---------------------------------- |
| **设计目的** | .NET 6+ 专门为定期执行设计的计时器                 | 通用延迟方法                       |
| **精度**     | 高，系统时钟驱动                                   | 受任务调度影响，误差累积           |
| **漂移问题** | **无累积漂移**（从系统时钟对齐）                   | **有累积漂移**（延迟包括执行时间） |
| **跳过机制** | 提供 `WaitForNextTickAsync` 返回 bool 指示是否跳过 | 无内置跳过机制                     |
| **异步支持** | 原生异步等待                                       | 原生异步等待                       |
| **资源消耗** | 较低                                               | 较高（每次循环创建新任务）         |
| **取消支持** | 通过 CancellationToken                             | 手动检查                           |

**Task.Delay 的漂移问题**：

```csharp
// 有漂移问题
while (!stoppingToken.IsCancellationRequested)
{
    await DoWork();           // 假设执行需要 500ms
    await Task.Delay(1000);   // 等待 1000ms
    // 实际周期 ≈ 1500ms，不是期望的 1000ms
}
```

**PeriodicTimer 正确用法**：

```csharp
// 无漂移，精确 1 秒周期
using var timer = new PeriodicTimer(TimeSpan.FromSeconds(1));
while (await timer.WaitForNextTickAsync(stoppingToken))
{
    await DoWork();  // 即使 DoWork 耗时 500ms，下次周期仍然从 1 秒起点计算
}
```

**选择建议**：

- 需要精确周期性执行 → `PeriodicTimer`
- 一次性延迟或简单定时 → `Task.Delay`
- 不需要高精度周期 → 两者皆可

## 26. 什么是 HSTS？

**HSTS (HTTP Strict Transport Security)** 是一个安全机制，强制浏览器只能通过 **HTTPS** 访问网站，禁止使用 HTTP。

**工作原理**：

1. 浏览器首次通过 HTTPS 访问网站
2. 服务器返回 `Strict-Transport-Security` 响应头
3. 浏览器记住该网站，在未来指定时间内自动将所有 HTTP 请求转换为 HTTPS

**响应头示例**：

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

| 指令                | 说明                               |
| ------------------- | ---------------------------------- |
| `max-age`           | 缓存时间（秒），如 31536000 = 1 年 |
| `includeSubDomains` | 应用到所有子域名                   |
| `preload`           | 允许加入浏览器预加载列表           |

**ASP.NET Core 启用 HSTS**：

```csharp
// 仅在 Production 环境中启用
if (!app.Environment.IsDevelopment())
{
    app.UseHsts();
}

// 自定义 HSTS 配置
builder.Services.AddHsts(options =>
{
    options.MaxAge = TimeSpan.FromDays(365);
    options.IncludeSubDomains = true;
    options.Preload = true;
    options.ExcludedHosts.Add("localhost");  // 排除本地开发
});
```

**注意**：开发环境不建议启用 HSTS，因为浏览器会强制 HTTPS，影响本地调试。

// 方法一：PhysicalFile - 返回服务器物理路径的文件
[HttpGet("download/{filename}")]
public IActionResult DownloadFile(string filename)
{
    var filePath = Path.Combine(_webHostEnvironment.WebRootPath, "files", filename);

    if (!System.IO.File.Exists(filePath))
        return NotFound();

    var mimeType = "application/octet-stream";  // 通用二进制类型
    return PhysicalFile(filePath, mimeType, filename);
}

## 28. 如何通过 API Endpoint 接收文件？

**方法一：IFormFile（单个文件）**

```csharp
[HttpPost("upload")]
[Consumes("multipart/form-data")]
public async Task<IActionResult> UploadFile([FromForm] IFormFile file)
{
    if (file == null || file.Length == 0)
        return BadRequest("No file uploaded");

    // 验证文件大小（5MB）
    if (file.Length > 5 * 1024 * 1024)
        return BadRequest("File too large");

    // 验证文件扩展名
    var allowedExtensions = new[] { ".jpg", ".png", ".pdf" };
    var extension = Path.GetExtension(file.FileName).ToLowerInvariant();
    if (!allowedExtensions.Contains(extension))
        return BadRequest("Invalid file type");

    // 保存文件
    var fileName = $"{Guid.NewGuid()}{extension}";
    var filePath = Path.Combine(_webHostEnvironment.WebRootPath, "uploads", fileName);

    using (var stream = new FileStream(filePath, FileMode.Create))
    {
        await file.CopyToAsync(stream);
    }

    return Ok(new { fileName, size = file.Length });
}
```
